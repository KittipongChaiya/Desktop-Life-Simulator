==================================================
Desktop Companion Architecture Extension
==================================================

Implement the following architectural requirements.

These are infrastructure requirements.

No new user-facing functionality is required in this phase.

==================================================

1. Future-Rebindable Hotkey Architecture
   \==================================================

Current shortcuts

F11
Work Mode

F10
Quick Hide

Ctrl+Shift+C
Click Through

are the DEFAULT bindings only.

They must NOT be hardcoded throughout the application.

Instead, design the system so future versions can support user-configurable shortcuts without architectural changes.

==================================================
Requirements
==================================================

Introduce a ShortcutAction abstraction.

Example

ShortcutAction.WorkMode

ShortcutAction.QuickHide

ShortcutAction.ClickThrough

Create a centralized ShortcutManager.

The application should bind:

ShortcutAction

↓

Current Key Combination

The implementation should avoid direct checks such as:

if key == F11

or

if key == F10

throughout the codebase.

All shortcut resolution must pass through the ShortcutManager.

==================================================
Persistence
==================================================

Shortcut bindings should be loaded from configuration.

For Version 0.1

Default bindings are fixed.

No UI is required.

No rebinding screen is required.

Configuration may simply load the default values.

Future versions should only need to replace the configuration source.

==================================================
Documentation
==================================================

ADR-014 should explicitly state:

Current shortcuts are defaults only.

Shortcut actions are stable identifiers.

Key bindings are replaceable configuration.

Future versions may expose a Settings UI without changing application architecture.

==================================================
Acceptance Criteria
==================================================

✓ Only one place defines physical keys.

✓ Gameplay code references ShortcutAction only.

✓ Future rebinding requires no gameplay changes.

✓ No duplicated key constants.

================================================== 2. Desktop Companion Settings Separation
==================================================

Desktop Companion preferences are NOT gameplay data.

They must never be stored inside save files.

They must never affect deterministic simulation.

They belong to the application itself.

==================================================
Settings Storage
==================================================

Create an application settings model.

Example categories

Desktop

Overlay

Window

Input

Future Audio

Future Graphics

Desktop Companion settings should include

Opacity

Window Position (if available)

Last Work Mode preference

Future Shortcut Bindings

Future Overlay Preferences

These settings persist independently of game saves.

==================================================
Save System Separation
==================================================

Game Save

contains

World

Simulation

Desktop Settings

contains

Opacity

Window Preferences

Overlay Preferences

Shortcut Bindings

Desktop Modes

Loading a save

must never overwrite desktop settings.

Deleting a save

must never delete desktop settings.

Creating a new world

must preserve desktop settings.

==================================================
Architecture
==================================================

Simulation

must never import

DesktopSettings

Window APIs

Electron APIs

Platform Preferences

Platform code may read settings.

Simulation must remain platform-agnostic.

==================================================
Future Extensibility
==================================================

Design the settings model so future versions can add:

Audio Settings

Graphics Settings

Language

Accessibility

Notification Preferences

without breaking compatibility.
