Phase-02.5 is complete. Do NOT begin workers, inventory, economy, buildings, or UI interactions yet.

Begin Phase-03: World & Crop Domain.

This phase establishes the first gameplay domain model that every later system will build upon.

==================================================
Objectives
==================================================

Design and implement the domain model for:

- World
- Tiles
- Crops
- Crop lifecycle
- Crop growth simulation

No player interaction beyond deterministic commands.

No rendering changes.

No gameplay UI.

No inventory.

No workers.

No economy.

==================================================
Architecture First
==================================================

Before implementation, determine whether the world model introduces an irreversible architectural decision.

If yes, create:

ADR-009-world-model.md

Only if justified.

Do NOT create an ADR merely because a new file exists.

If the existing ADRs already cover the decision, extend them instead.

==================================================
World Model
==================================================

Design immutable concepts where appropriate.

Support:

World

Chunk

Tile

TileCoordinate

TileState

TileOccupancy

OwnedPlot

The world should be independent from rendering.

Rendering consumes world state.

The world must not know PixiJS.

==================================================
Tile State
==================================================

Each tile should support only the minimum required states.

Example:

Empty

Tilled

Planted

Growing

HarvestReady

Future states such as water, fertilizer, roads, buildings and decorations must be possible without redesign.

Avoid enum explosion.

==================================================
Crop Model
==================================================

Represent crops as data.

Each crop type defines:

id

displayName

growthStages

growthDuration

harvestYield

season

futureTags

No inheritance hierarchy.

Prefer composition and data-driven definitions.

==================================================
Crop Instance
==================================================

Each planted crop stores only runtime state.

For example:

cropType

tile

plantedTick

growthStage

health

Do not duplicate static crop data.

==================================================
Growth System
==================================================

Implement deterministic growth.

Growth depends only on:

Simulation Tick

Crop Definition

Planted Tick

No randomness.

No weather.

No fertilizer.

No workers.

No real-time clock.

Offline progression compatibility must be preserved.

==================================================
Commands
==================================================

Introduce command handlers only.

PlantCrop

HarvestCrop

Reject invalid commands.

Examples:

Plant on occupied tile

Harvest before ready

Plant outside owned plot

Plant unknown crop

Commands publish events through ADR-008 Event Bus.

Only introduce events with immediate producers and consumers.

==================================================
Testing

growth progression

growth completion

invalid planting

invalid harvest

multiple crops

deterministic simulation

offline progression

stable serialization

edge cases

Target:

100% deterministic behavior.
