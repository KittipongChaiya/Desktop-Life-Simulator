## [Unreleased]

### Added

- **Phases 55–61 — the content itself** (no schema change; ADR-046): the
  registries roughly tripled, and every one of ADR-046's ten rules is now
  enforced rather than reported.

  | Registry         | v0.5 | v0.6    |
  | ---------------- | ---- | ------- |
  | Crops            | 4    | **12**  |
  | Recipes          | 2    | **9**   |
  | Items            | 13   | **36**  |
  | Buildings        | 10   | **13**  |
  | Expedition sites | 3    | **6**   |
  | Authored quests  | 1    | **5**   |
  | Sprites          | 242  | **298** |

  **Every season now offers five or six plantable crops**, against two in spring
  and winter before. The prices are derived rather than chosen: fitting the four
  v0.1 crops gives `profit/sec = 0.078 × (seconds/90)^0.23`, and each new crop
  declares a growth time and a seed cost with its sale price falling out of that
  curve — so `GAME_DESIGN.md` §3.2, the decision that makes going away optimal,
  holds across all twelve rather than merely inside the new ones.
  `tests/crop-curve.test.ts` asserts it for the first time in six versions.

  **What a seasonal choice can be, given §3.2 fixes the rate ordering:** the
  axis is capital. Leek and wheat have identical growth times and identical
  profit per second, and the leek costs half as much to plant.

  **Production went from one two-step chain to four**, one of them four items
  deep — flax → linen fibre → thread → cloth — which is the first thing in the
  game that asks a player to run two buildings in series. Every factory now runs
  at least two recipes, so owning one is a decision rather than a switch.

  **Three buildings above the Market Stall**, which had exactly one. The Granary
  is the one that is not more processing: a full container is the single
  bottleneck that makes a player's absence worse rather than better.

  **The arc was re-measured against every crop a new farm can plant** and did
  not move — 10 to 17 minutes for a perfect player, against ~12 at phase 31.
  **So no balance was changed.** ADR-046 §4 grants the authority; ADR-044 sets
  the standard, and the measurement asked for nothing.

  **Two rules were amended rather than met**, both recorded with the reasoning.
  R-05's "distinct bottleneck" was not checkable, so a building's kind is now
  derived from its definition. R-09 asked for authored audio timbre — which
  ADR-043 established at v0.5 cannot be evidenced by a session that cannot hear
  it — and now asks that every sound has a trigger instead.

  **Findings the gates produced, none of which a passing suite would have
  shown:** a soft-lock in the product (`GAME_DESIGN.md` §6.4a) where a farm can
  spend below the price of a seed with nothing planted and never recover; a
  six-version-old bug in the progression model that spent past that same line; a
  `peakCoins` diagnostic that had been printing the starting float for every
  failing run; two expedition destinations refused at registration for
  over-filling a worker; and three UI tests that were pinning list positions,
  one of which would have gone permanently green for the wrong reason.

- **Phase 62 — the version string, four milestones late** (ADR-028 §5.1):
  `package.json` read `0.1.0` while v0.5's game shipped on top of it, because
  `tests/signing-exception.test.ts` fails at `0.3.0` without a certificate. The
  guard worked exactly as designed and the outcome was still wrong — the
  SHIPPING VERSION lied instead of the signing status. The owner extended the
  exception through v0.6; the version now reads `0.6.0`.

  **Extending it now costs a written row.** ADR-028 §5.1 carries a table of
  every extension with its date and authority, and the guard requires the
  current expiry to appear in it. Two further checks: `PLAN.md` §0 must name
  code signing as a blocker while the exception holds, so a resuming session
  inherits the sentence rather than the surprise. Verified by inversion —
  raising the expiry without writing the row fails the suite.

  Nothing in ADR-028 §3's threat model changed. The build is unsigned, and the
  exception blocks publication rather than development.

- **Phase 54 — the content census** (no schema change; ADR-046): v0.6 opens as
  a **content tier** — the first version that adds no simulation system, and
  therefore the first whose scope cannot be bounded by "the system works."

  `VISION.md` §4 was amended first, as `PLAN.md` §9.3 requires. That amendment
  also records that the same rule was **not** followed when v0.5 opened, rather
  than backdating the row and pretending it was.

  **What opened the version is a count.** At v0.5's close the whole content set
  was 4 crops, 6 purchasable buildings, 2 recipes, 1 authored quest chain, 3
  expedition sites, 3 resource nodes, 4 residents and 11 placeholder sounds.
  Five versions built content-_driven_ systems; ADR-035's factory model, built
  for chains, runs one two-step chain.

  **ADR-046 bounds the version with ten rules rather than ten targets.** Each
  states a property the content set must have — three plantable crops per
  season, no strictly dominated crop, two chains of real depth, an authored
  quest chain per resident — and the count falls out. A version scoped by a
  feeling either stops early or never stops.

  **`tests/content-census.test.ts` carries all ten from day one, gated on
  `PLAN.md` §0's own phase table.** Marking a phase COMPLETE turns its rules
  into hard assertions, so "phase complete" and "the phase's rule holds" are one
  claim instead of two that drift. No `it.skip`: a pending rule still runs,
  still prints its violations, and still asserts that it is legitimately
  pending. Verified by inverting the gate — marking phase 55 complete early
  fails with `core:spring has 2 plantable crops`.

  **The census corrected its own author twice before enforcing anything.** The
  scoping document said six buildings; there are ten, four of them the town's at
  zero cost. It said every season offers exactly two plantable crops; summer and
  autumn offer three. And it said the two are "strictly ordered," implying one
  is simply better — the dominance check written for R-02 passes today, so the
  defect is **volume, not domination**. R-02 is carried anyway, as a guard
  against fixing R-01 with twelve crops in a neat power ordering.

  **The v0.5 id set is pinned as a floor.** ADR-026 makes a `ContentId`
  permanent — an instance in a live save stores the id and resolves it at load,
  so renaming `core:wheat` orphans every wheat in every save. v0.6 adds and
  never renames or removes, and the test is what makes that a fact rather than
  an intention.

- **Phase 53 — "Start New Game"** (no schema change; ADR-045): a button in the
  settings panel that ends the current farm and starts another. Owner-requested
  after the v0.5 RC.

  **It asks for what this project's persistence design calls the
  catastrophe.** `SAVE_FORMAT.md` has said "NEVER a new game" since v0.1, and
  five versions of load-path work exist to make sure a player with a farm never
  comes back to an empty one. ADR-045 draws the distinction: the prohibition is
  about a farm disappearing **without anybody asking** — a corrupt file, a
  failed parse, a directory read as "new player" — and a player deliberately
  ending their own farm is the opposite situation. The bar it sets survives
  intact in two properties.

  **The button archives; it never deletes.** Every save artifact moves to
  `saves/archive/<timestamp>/`, including the pre-migration backups ADR-027 §2
  keeps indefinitely, so a player who regrets the click has their world in a
  folder. **Nothing this application does removes a farm from disk.**

  **It cannot be pressed by accident.** No confirmation primitive exists
  anywhere in `src/`, and neither obvious one is right here — a modal in a
  frameless always-on-top overlay is the wrong shape, and `window.confirm`
  would block the thread the simulation runs on. The control arms on the first
  press and fires on the second, disarming on a timeout and whenever the panel
  closes, so a stale arm cannot be inherited by somebody who walked away.

  **A latent defect fixed on the way past:** `pruneBackups` keeps the highest
  ticks and a new game starts at tick 0, so a reset that left `backups/` in
  place would have deleted the NEW farm's copies while retaining a world that
  no longer existed — the new farm would have accumulated no backups at all.

  The reset is a **reload**, not a live world swap: every store on `World` is
  `readonly`, so a reset is a new world rather than a modified one, and
  `bootApplication()` already builds one correctly on every launch. The
  sharpest hazard was the sequencing — the renderer holds the old world while
  its files move, and any save trigger in that window writes it straight back.
  Main stops the cadence and **refuses writes** until the reloaded renderer
  asks for its saves; proven against the running app, and checked by inverting
  the guard to confirm the test fails.

- **v0.5 phase 52 — the release candidate** (no schema change;
  `RELEASE-v0.5-RC.md` is the deliverable): every gate re-run fresh rather than
  cited. Unit **3,309 passed / 0 failed** across 260 files; E2E **84 passed, 4
  skipped, 0 failed** with **no flakes**; coverage **94.98% lines / 86.58%
  branches** with all nine per-area thresholds met; a production build launched
  and stayed up; typecheck ×3, lint, format, boundaries, cycles, the
  `v1 → v14` migration chain and `npm audit` all clean.

  **Four findings, three of them about gates that had never actually been
  run.** The coverage gate went red with five timeouts under instrumentation
  (~3.3×), and the obvious fix — excluding the long-runs, as `memory-longrun`
  already is — was tested rather than believed and turned out to drop
  `src/persistence` branches to 88.47% against a 90% threshold, because
  `catch-up-factories` reaches `catch-up.ts` gaps nothing else does;
  `tests/long-run-budget.ts` gives a test one budget per run instead.
  **Asset regeneration could not have been byte-identical**, and had not been
  for the whole art track: `lint-staged` ran Prettier over the generated
  `.anim.json` sidecars, so every commit and every regeneration flipped six
  files — and separately, **two placeholder generators from v0.1 were still
  writing the same filenames as the production ones**, so running either
  reverted live art to grey blobs. Both deleted, and
  `tests/art-regeneration.test.ts` now fails on a single moved byte.
  **Phase 46's performance regression does not reproduce** when measured on an
  idle machine — see the phases 40–46 entry.

  Also amended: **ADR-042 §4**, which described a legacy-overlap mechanism
  `deserialize.ts` does not use. Same guarantee, simpler mechanism, and the ADR
  was the thing that was wrong; `tests/legacy-overlap-load.test.ts` pins the
  behaviour on the load path, which is where an old save actually arrives.

  **Two success criteria are OPEN, not met and not substituted.** The "oh, I
  see" moment at the first hire and a tester returning on a second day are
  human-playtest evidence, which ADR-040 forbids marking PASS from a session
  with no human in it. Perceptual acceptance of the visual overhaul is in the
  same class.

- **v0.5 phases 40–46 — the world stops being a grid** (no schema change;
  ADR-042 governs): the cozy pass made the assets better and did not make the
  game look like a world, and the owner's correction identified why. The
  problem was never asset quality — it was that **one tile meant one object**,
  so a mill and a seed bin were the same size and the player was looking at a
  spreadsheet with pictures in it. No amount of prettier sprites fixes a
  content model.

  ADR-042 separates the grid the simulation needs from the world the player
  sees, and **takes nothing away from the grid**: pathfinding, occupancy,
  collision, farming, logistics, worker AI and the save format are untouched. A
  building's tile became its ORIGIN rather than its extent. Buildings now
  declare a `footprint` — shed and hut 2×2, stall and kitchen 3×2, mill 3×3,
  cottage 2×2, castle 4×3 — and a definition that declares nothing is still one
  tile, so a v0.4 content pack keeps working untouched.

  **The footprint is content, and it is derived.** A saved building records the
  same definition id and origin tile it always did; the rectangle is looked up
  on load. That is why a version that changed how the whole world looks **added
  no schema version** — the same rule (ADR-009 §1) that keeps tilled soil, tile
  variants and worker rigs out of the file.

  Rendering gained **one sorted layer, one sort key, one anchor**: everything
  that stands in the world lives in `world` and sorts against everything else
  by its base position in world pixels, so a walking worker and a standing
  building are measured on the same scale; `depth.ts` is the only place that
  key is computed; and `anchor.set(0.5, 1)` means art can be as tall as it
  likes and grows upward out of the footprint rather than out of the world. The
  buildings slice publishes `footprintWidth` and deliberately not
  `footprintHeight` — width centres the sprite, height is the art's business,
  and a canopy overlapping the tiles above it costs the simulation nothing
  because the simulation was never told about the canopy.

  **The cost was measured twice, and the second reading is the one that
  counts.** Phase 46 reported a real regression — tick average 0.063 → 0.104
  ms, unattended CPU 0.595% → 1.058% — and flagged that its first reading had
  been taken while the machine was building. Re-measured at the RC on an idle
  machine, **it does not reproduce**: tick average **0.060 ms**, unattended CPU
  mean **0.533%**, and the v0.4 full-load scenario now runs at **0.145 ms**
  against v0.4's own 0.187 ms, with 547 visible sprites. The footprint
  hypothesis (a 3×3 mill blocking nine tiles where it blocked one) was stated
  as unproven and is withdrawn. One increase is real and consistent: **heap
  12.8 → 14.5 MB**, most plausibly the art set growing 166 → 237 sprites,
  against a 25 MB ceiling. `PERFORMANCE.md` §18 carries the whole comparison,
  including what the method got wrong.

  Running the real game found what no unit test could: a cool grey
  `UNOWNED_TINT` washing most of the screen, decor that stopped nine rows short
  of the map's bottom, worker rigs that drew nothing because their `.anim.json`
  sidecars had been written by hand and never existed for the new keys, and six
  buildings placed one tile apart in a fixture that footprints no longer allow.
  **Perceptual acceptance of the visual work is the owner's call** — ADR-040
  forbids marking human-playtest evidence PASS from a session with no human in
  it, and everything measurable was measured.

- **v0.5 phases 47–51 — the playable cut** (no schema change; ADR-043 and
  ADR-044): the version's remaining half, which is about the person playing
  rather than the thing they look at.

  **Audio that survives a workday** (ADR-043): eleven sounds each played from
  one buffer meant every harvest was bit-identical to every other harvest —
  survivable in twenty minutes and the whole problem in eight hours, because
  identical repetition is what turns a sound somebody liked into a sound they
  mute. Repeated world sounds now vary ±6% in pitch, derived from a per-sound
  play counter through the same hash the world already uses for decor and tile
  variants, never `Math.random` — so the same farm sounds the same on every
  launch and the rule is testable. Signals (ui, error, notification) and the
  ambient bed deliberately do not vary: a statement that moves reads as a
  fault, and a bed whose rate changed would shift pitch mid-weather. The rule
  is by CATEGORY, so a sound added later inherits it. **The replacement path is
  now verified rather than promised** — dropping a real `.wav` into
  `assets/src/audio/` copies it through instead of synthesising, both
  directions exercised; that promise is the entire justification for shipping
  placeholder sound and nothing had ever checked it. **Timbre is not improved
  and is not claimed to be**: I cannot hear it, and ADR-040 says evidence
  needing a human is never PASS from here.

  **Zone painting**: `setWorkerZone` shipped in v0.3 and no player could ever
  call it — choosing tiles is a map interaction, and the panel shipped roles
  alone. Arm from the panel, drag a rectangle on the farm, Shift erases, Escape
  finishes. The drag's start is state; the moving corner is not, which is what
  stops every React subscriber re-rendering on every mouse move. One real bug
  found by building it: the camera takes `setPointerCapture` on any world drag,
  and capture fires `pointercancel` on every other listener, so the rectangle
  was abandoned before it had a second corner. One real documentation defect
  too — `workers-slice.ts` claimed a zoned worker reports a `null` role; the
  matcher had always ignored zones, and a test built on that sentence cost an
  hour concluding the feature was broken when the comment was.

  **"What now?"** (amends ADR-034 §7): the game never told a player what to do
  next, which is fine for the person who built it and hostile to everyone else
  — a farm with money in the bank, an empty field and no workers looks exactly
  like a farm that is finished. One line in the status bar, derived from the
  snapshot the HUD already holds: no objective state, no progress record, no
  save change, nothing to migrate. §7 forbade a quest journal WINDOW and that
  judgement stands; this is deliberately smaller — one sentence, no log,
  nothing to dismiss, and **it renders nothing most of the time**, which is
  what lets it live in the bar at all. Ordering it turned it into onboarding
  for free: buy seed → plant → wait → sell → hire, where each step is the
  state the previous one leaves behind, so there is no tutorial mode, nothing
  to skip and nothing to resume. Running it caught the version of this feature
  that would have poisoned it: the first draft counted every posted board offer
  and told a brand-new farm with an empty inventory that the board wanted
  something it could deliver.

  **The arc, timed** (ADR-044): a perfect player reaches stage 4 in about
  **twelve minutes** against a design document claiming "3 hr+" — a number four
  versions were built on and nobody had ever checked. Both are wrong for the
  same reason: neither describes a person. Twelve minutes is a LOWER BOUND for
  a model that never mis-clicks and harvests on the exact tick of maturity, and
  what a real player takes has never been measured at all. **The balance was
  therefore not changed** — tuning an economy against a perfect-player bound is
  guessing with arithmetic, and the stall's price reaches contracts, factory
  payback and expedition funding, which makes it the owner's call. The
  measurement bought a guard instead: the arc test now asserts a floor as well
  as its four-hour ceiling, because the ceiling catches an arc that got slower
  and nothing caught one that fell over.

- **v0.5 phases 32–39 — the cozy pass** (no schema change; ADR-041 governs): a
  visual revision of the whole game at the owner's direction, and the finding
  that shaped it is that **the direction was never wrong — the assets never
  reached it**. `ART_DIRECTION.md` §2 has said "cozy farm, made with care" since
  phase-05.5. The reason five versions of production did not get there is in
  the code rather than in the documents: `pixel-art.mjs` offered `rect`,
  `ellipse` and `outlineSilhouette`, so every asset in the game was a box or a
  blob in a uniform keyline, and **five buildings were the same building ±10
  px**. The vocabulary was the ceiling. `pixel-craft.mjs` is the new one —
  ordered dither, organic blobs, polygons, five material patterns, selective
  outline — and ADR-041 amends exactly one locked rule to allow it (R-04:
  outlining becomes SELECTIVE, because a keyline traced round every object is
  what makes a scene read as stickers laid on a background). The palette gained
  a warm stone ramp, two more woods, a roof family and flower accents, all by
  R-08's reviewed process.

  **Rebuilt:** all six terrain tiles, with variants for grass, wild and tilled
  ground chosen per tile by a hash of the tile index — derived, never stored,
  the same argument ADR-009 §1 makes for tilled soil; six buildings, each on a
  silhouette argument rather than a decoration (the mill is the only thing with
  a wheel, the kitchen is a lopsided mass round a lit oven stack); three worker
  rigs, so a farm stops being staffed by one person printed several times; farm
  and town prop sets, so decor knows about all three of the world's regions
  instead of one; and the HUD's entire palette.

  **What the pass found is more interesting than what it drew.** The UI palette
  in `COLOR_PALETTE.md` §6 had never been implemented — not one stylesheet used
  a single value from it, and the HUD had been a cool grey dashboard since
  phase-05.5c. The accessibility gate was measuring a hand-copied colour list
  that its own header admitted could drift, and only ever checked a white
  desktop, so a light theme would have passed it while being illegible on a
  dark one. Decor placement filled from tile 0 and stopped at its cap, so **the
  last nine rows of the map had no decoration at all** and every prop set added
  made the strip taller. And `UNOWNED_TINT` was a cool grey at 42% brightness
  multiplied over everything outside the plot — which is most of the screen —
  so the world read as dark and sterile. That last one was invisible to every
  contact sheet ever generated, **because a contact sheet has no owned plot in
  it**, and it was found in the first ten seconds of the first screenshot of
  the running game. `visual-review.spec.ts` makes that screenshot a gate.

  **Three prototype iterations are recorded in `ART_DIRECTION.md` §9.2 rather
  than rediscovered:** a 32 px ground tile cannot carry an ordered dither (a
  4×4 Bayer matrix repeats eight times across it and resolves into a
  cross-hatch), solid tonal blobs read as polka dots, and ground texture is
  hand-placed low-contrast clusters. §9.3 records what a multiply tint can and
  cannot do to a season, and the correction that rain was never invisible —
  `rain-view.ts` has drawn it since phase-12d; what it lacked was a form that
  survives an idle overlay, which is what the new ground tint is.

  **The idle budget did not regress, measured rather than assumed** (ADR-041
  §5): unattended-farm CPU mean 0.633% → 0.595%, max 1.066% → 0.835%, heap 15.4
  → 12.8 MB, tick average 0.184 → 0.175 ms. Unit suite 3,224 passing; e2e 80
  passed, 4 skipped. New gates: `palette-lock.test.ts` (R-08 and R-09 as a
  test, which caught two of this pass's own proposed colours sitting inside the
  reserved signal set), the HUD's warm-palette guard, whole-map decor coverage,
  and the live visual review.

- **Phase 30 — the v0.4 release candidate** (no schema change; `RELEASE-v0.4-RC.md` is the deliverable): the version closed against evidence, every `PLAN.md` §8 gate **re-run fresh rather than cited** — the v0.3 lesson, applied at phase 24 before v0.4 added a system and due again at the other end. The principle underneath is the one the owner set for the version: _never accept "documented as implemented" as proof of "actually implemented"_; a gate cited from a phase document is a claim about the past, and a gate run today is a fact about the repository. **Almost nothing was wrong with the build** — typechecks, lint, boundaries, cycles, `npm audit` (0 vulnerabilities, production tree), the `v1 → v14` migration chain against every golden fixture, a **production-build** startup, the full e2e suite (**78 passed, 4 skipped**, every skip environment-gated with its reason), and asset regeneration all clean first time, with the art **byte-identical** to what is committed. **The coverage gate came up RED**, exactly as it did at the v0.3 RC and in the same directory: `src/sim` branches at 83.44% against 85%, `src/persistence` at 87.79% against 90%. The gap had one shape — v0.4 added four command modules and a relayout migration, and every one was tested on what it DOES far more than on what it REFUSES, which is what a phase always does because the happy path is the feature and the guards are what nobody demonstrates. Sixty-eight tests closed it (final: **86.68% branches, 95.30% lines, 3,159 tests across 244 files**), and every one asserts a behaviour rather than colouring a line. **The fresh runs earned their keep three times, and twice a branch nobody had run turned out to be a defect rather than dead weight.** First, `sprite-keys.test.ts` was widened into a gate that cannot need widening again: its registry-based checks were written in phase 25 for exactly the class of defect phase 27 then shipped anyway, because the gate enumerated registries and the resource-node registry was new — **a gate that lists what it knows about cannot know about the next thing** — so it now scans the SOURCE for anything shaped like a sprite key (54 today, all resolving), covering registries, render-time overrides, decor's prop table, and whatever a future view hardcodes. Mutation-verified against a typo in a place no registry check could ever have looked. Second — found while writing a coverage-closing test — the registered `sendExpedition` parsed its destination with `asContentId`, which THROWS on a malformed id, so a command carrying `"not-a-content-id"` crashed inside the dispatcher instead of being refused, in violation of ADR-010 §5; every source arriving at that door is untrusted, not just the player's. Third, and blocking: reading phase 28's own deserializer against the invariant it created found a comment reading _"there is nothing to reconcile here"_ — and there was. Expeditions introduce a cross-field invariant, **a worker is `Away` if and only if a trip names them**, and the loader trusted it; a worker marked away with no trip behind them is skipped by the FSM by design and brought back by nothing, so **a hand the player paid for becomes permanently unusable** with nothing on screen to explain it. That is the data-loss class §8 makes blocking without exception. Four corruptions, four repairs, each chosen to restore what was paid for without inventing anything — an orphaned away worker returns to Idle, a trip whose worker is not away is honoured because the supplies were already spent, a trip naming nobody is dropped, and a departure later than the world's tick is clamped to now — and all four tests are red with the reconciliation removed. **The economy was validated rather than asserted**: the useful part was finding a claim narrow enough to check — _every profitable loop is gated by TIME, and every loop gated only by COINS is at best break-even_ — since the game is meant to profit, and what must not happen is a player with a million coins and no workers clicking themselves richer. Eleven claims: the seed round trip never profits (single or repeated fifty times), the **recipe graph has no cycle** (walked as an item graph, because a cycle can span several recipes and no single one would look wrong), selling drives its own price down, and every declared source — nodes, expeditions, crafts, crops — is gated by time rather than coins. One assertion was corrected **against the design rather than the reverse**: the repeated-sell loop asserted a strict fall every round and failed at round four, because the multiplier has a FLOOR — the brake is a floor and not a cliff, so a glut is worth less rather than worthless. **The four success criteria: three PASS and one PARTIAL**, the partial stated as what it is rather than rounded up. A production chain runs 576,000 unattended ticks without jamming; exploration feeds the farm through gathering and expeditions with the rate rule holding every destination inside half-to-double a forager's; **515 visible sprites** under full v0.4 load. Criterion 4 is PARTIAL because offline a chain's **buffers** are credited and the chain is not — it under-credits deliberately, which `GAME_DESIGN.md` §9.2 permits and the reverse would not, since every wrong guess in a hauling model lands on the side that credits work the simulation would have refused. **No version bump, by design**, for the third version running: ADR-028's signing tripwire holds `0.4.0` hostage to the owner's certificate, the repository ships version-stamped `0.1.0` — four versions of game behind its own version string — and the critical path to a published release still runs through that purchase and nothing else.

- **Phase 29 — the renderer's boundary, and not threading the simulation** (ADR-039; no schema change): the phase existed to answer one question, and it was **measured rather than argued**. ADR-003 §2 pre-committed the migration trigger two versions early — _"move the simulation to a worker when a p99 tick exceeds 3 ms, or when tick execution measurably delays frame presentation"_ — and `PLAN.md` §5.1 sequenced this phase LAST in v0.4 so the version's own load would exist to test it against. Taken in the **running app** on a save the game could genuinely have written (36 crops, six hands, thirteen buildings, a three-step chain with **both links routed**, a forager working the wilds, a hand away on an expedition, contracts on the docket, under criterion 12's full presentation load): p50 0.2 ms, p95 0.3 ms, **p99 0.4 ms**, max 6.9 ms, 1,272 samples, **93 FPS**. **The trigger is NOT MET** — roughly seven times inside — and the second clause fails too, since the renderer held 93 FPS with the simulation ticking at 20 Hz on the same thread. Headless would have answered the wrong question: `PERFORMANCE.md` §16's 0.53 ms comes from a Node run, and the frame-presentation clause only exists where a renderer and a simulation share a thread. - **Phase 28 — world map & expeditions** (ADR-038; schema **v13 → v14**, the chain's smallest link: one empty collection): v0.4's last milestone, and the one that makes _"the player gains reach"_ mean somewhere you cannot walk. **The map is a LIST, not more grid** — the obvious reading of "world map" is more tiles, and the grid is already 112×64 after two relayout migrations that each re-encoded four dense arrays and remapped every stored index, so a third would be the most expensive possible way to express _far away_, which `travelTicks` expresses in one integer. The cost is stated rather than glossed: **you never see the place.** **Only the departure is stored** — `{ worker, destination, departedTick }` — and the return tick, the haul, and the time remaining are all arithmetic on it, which is **ADR-037's model applied to TIME instead of SPACE**. That matters more here than anywhere else in the version: an expedition is by construction the longest-running thing in the game, so it is the mechanic most likely to complete while the player is at work, and derived it is not a threat to _"offline catch-up remains accurate"_ at all — _has this returned by tick T_ is a comparison. Rolled on arrival, the roll would have to happen inside catch-up, and a catch-up that performs draws can drift from a live run; there is a test that runs one world through every tick of a trip and jumps another straight over the gap and asserts the farm ends up holding the same goods. The haul is `hash(seed, worker, departedTick)` over a declared band and **consumes no RNG draw** — the same argument for the third time, since `world.rng` is a stream whose position is part of the save. The band **never includes zero**: a trip that came back empty would punish a decision made an hour earlier, so the floor is clamped to at least one of anything declared. **A worker away is ABSENT from the workers slice**, not present with a flag — ADR-031's shape for the sleeping town, so no view can draw a hand who is not there. **THE RATE RULE IS A TEST, NOT A PARAGRAPH:** the real cost of an expedition is the worker, so every destination's haul value per tick of worker time is asserted inside half-to-double a forager's — above the ceiling the correct play is to send everyone away and let the farm rot, below the floor nobody goes. The anchor was **measured before it was chosen**: farming was the obvious one and is wrong, because a 24-tile wheat farm with three hands earns **0.0033 coins per worker-tick** over 200,000 ticks, twenty times below a forager's rate at base price, since the farm's coin figure is dominated by the sale multiplier decaying under its own volume — anchoring there would have measured the market rather than the mechanic. That rule then **chose the content**: a worker carries twenty items, so wood at 8 and stone at 14 cap a full pack at a few hundred coins and a wood-and-stone destination would have to be under two minutes away to pay its rate, which is a walk rather than an expedition — so the hauls are the scarce goods, ore and wild produce, and the wilds already supply the rest. Two guarantees the carry cap forced, both structural rather than hoped for: a destination whose **biggest possible** haul cannot fit an empty hold is refused at registration, and the send command refuses a worker who is still carrying — together making _the haul always fits_ a property, since ADR-011 §7 leaves no third option once a return exceeds the hold. Standing gates the map at the command boundary, locked destinations **visible with their requirement**, which gives the town's reputation a second consumer rather than inventing a progression axis. **The live pass found four defects in one sitting** — the fourth phase running that a screenshot has caught what a green suite did not: Send was enabled with nothing to outfit the trip (click, `MissingItem`, nothing happens — on a fresh world, the first thing a new player would try); the supplies check read `world.inventory` alone, which is the **phase-06 defect exactly, one system later**, so a player who had built a shed would find Send silently refused because their seed had been tidied away (it now checks and drains through the `heldForSale`/`sellableContainers` helpers selling and contract delivery use); **the hire price dropped when a worker went away**, because `hireWorker` charges `hireCost(workers.size)` while the panel priced off the slice that this phase's own design excludes them from, and the status bar read **"0 workers"** with a hand out at the delta, which reads as a worker _lost_; and the status bar wrapped, because the Map toggle was the element that pushed the row past its width. The transferable one: **a decision that makes something invisible has to be followed to every place that was counting it.** Reading catch-up against the phase then found **the third over-credit in `catchUpFactories`**, one phase 26 shipped: the model advanced crafts at `craftTicks` where the simulation runs them at **`craftTicks + 1`**, since a factory that completes on tick T is idle on T and cannot restart until T + 1 — measured off a live mill completing at 1201, 2402, 3603, 4804, a constant 1,201 gap for a 1,200-tick recipe. It survived because **the property fails on about one run in three, so a green run was never evidence**; both counterexamples are now pinned as deterministic examples, the cadence has a test that measures it rather than asserting a constant, and an example test that had been pinning the _model's_ answer (five crafts in `craftTicks × 5 + 2`) was corrected against a live run. Profiled at **p99 0.53 ms** under a real v0.4 farm — three hands, twenty-four crops — against ADR-003 §2's 3 ms trigger, which is **not met**. 3,083 tests across 239 files.

- **Phase 27 — the wilds & resources** (ADR-037, **amended twice during implementation, both times by measurement**; schema **v12 → v13**, the chain's second relayout): a third region of the map, with things in it worth going to get. The load-bearing decision is that **nothing about the wilds is stored** — `nodeAt(registry, seed, tile)` is a pure hash, so ~2,000 tiles of wilderness cost the save **zero bytes** and are exact after any absence, because _"is this node available at tick T"_ is arithmetic rather than a simulation to catch up. The hash consumes **no RNG draw**: `world.rng` is a stream whose position is part of the save, so drawing here would make what grows in the wilds depend on how many other things had happened first, and two worlds with one seed would diverge on the first weather roll. The one persisted thing is `harvestedAt`, pruned the moment a node regrows — otherwise it would be the one collection that grows with **playtime** rather than world size, which `SAVE_FORMAT.md` §3.4 names as the hazard; measured over 120,000 ticks with three foragers it settles at **132 entries**. Three node kinds (timber, stone, ore vein) at 6.0/4.5/3.0% of wild tiles, where scarcity is **time** and never a rarity roll — ore is the scarce one because it takes fifteen minutes to come back, and a player can learn that by watching. **The ADR was wrong about priority twice, and measurement said so both times.** §4 first put gathering above plant and till, reasoning that a rock outranks ground that will still be there tomorrow: measured, `dry-farm` earned **zero** and 28 catch-up assertions failed — the wilds start thirty-plus tiles out, so a worker who chose one did almost nothing else, and **distance is part of a band's priority in a way that is invisible in the reasoning**. Last-resort ordering fixed the earnings and not the shape, so **gathering is now opt-in and is the only band that is** — `core:forager` is the role that names it, and the parallel is the argument: hauling does not happen until the player declares a route, and neither kind of long-distance work should begin merely because nobody said no. **Then the phase's real finding: gathering worked perfectly and the wilds were invisible.** The hash placed nodes, the command took the yield, the forager walked out and came back carrying wood, and **2,937 tests were green while nothing drew a single node** — thirty-two columns of blank grass with a mechanic running behind them that no player could have found. That is phase-25's defect one phase later and worse, and the gate written for phase-25's bug (`sprite-keys.test.ts`) missed it because it only knew about **registries**; it now covers node sprites and the two render-time overrides that belong to no definition at all, both mutation-verified. **The gate you wrote for last phase's bug does not automatically cover this phase's version of it.** So: a node layer that computes positions from the seed and publishes only STATE — the new `wilds` slice carries which nodes have been worked and nothing else, as a **boolean and never a countdown**, since "ticks until regrown" would republish at 20 Hz for a whole regrow period (the defect ADR-005 §2 names by name); a worked node draws faded and small rather than hidden, because an empty tile says _nothing ever grew here_ and a player who felled a stand would think they had exhausted it; and wild ground is painted the way tilled soil already is — an override at draw time, stored nowhere, needing no migration — with a ragged drawn edge that may only reach **inward** of the straight gameplay edge, because rough ground with nothing on it is scrub while a node standing on mown farm grass is a lie about the ground. **Two things only the screenshots could have said:** decor no longer draws a tree or a rock **anywhere in the world**, because those were exactly the node sprites and identical trees either side of a boundary teach a player that trees sometimes work and sometimes do not — the rule is now _a tree or a rock is something you can work; everything else is scenery_, with the countryside keeping its prop density in flowers and bushes, so it reads as **meadow against forest**; and the densities were **cut by a third**, because a tile density is not a visual density — the tree crown overflows its tile and closes the gaps either side, so one tile in five rendered as a wall of canopy with a worker lost among the trunks. Three defects the tests found on the way: the gather command had no region check (`nodeAt` answers for any tile by design, so a node appeared to exist in the middle of the plot), the wilds projection had the same hole — which made it the third caller needing the boundary, now one named `isInWilds` — and `selectGather` skipped ADR-024's filter stage entirely, ignoring the very zone/shift/role inheritance §4 had promised. Profiled headless over 120,000 ticks, a forager crew is **marginally cheaper** than a farm crew (p99 **0.048 ms** against 0.066, both ~50× inside the 3 ms budget), because foragers walk where farmhands scan. 2,990 tests across 234 files.

- **Phase 26 — logistics & reservation** (ADR-036, **amended during implementation**; schema **v11 → v12**: routes, the route id counter, per-worker haul state): goods move between buildings without the player carrying them, and **v0.4's headline criterion becomes an executable test** — `tests/chain-longrun.test.ts` builds shed → mill → kitchen, routes both links, and runs 576,000 ticks (eight hours) asserting the chain is still producing in its final quarter, that reservations never exceed what a source holds, and that conservation holds at 1 wheat / 2 flour / 4 bread. The amendment is the phase's best decision: §4 specified a reservation **record** owned by a task and §5 a per-tick sweep to catch leaks; implementation found a stronger form, where a worker holding a `Haul` task for route R has **by that fact alone** claimed goods at R's source, and a worker whose `hauling` is R has claimed space at its destination. Nothing is recorded, so **nothing can leak** — release on every exit path becomes structural rather than disciplined, reservations survive save/load for free because tasks already do, and the sweep is **withdrawn**, since a sweep over derived state can only ever find nothing and keeping it would imply a leak class that no longer exists. Factories stayed **endpoints**: `world/endpoints.ts` answers what may be taken from a building and what may be given to it and knows nothing about recipes — the asymmetry (offer the output, accept into the input) is what stops a hauler taking back the flour it just delivered. What the end-to-end tests found that unit tests could not: **hauls never ran at all**, because ordinary tilling outranked hauling on any farm with untilled ground, so the declared ordering had to put hauling above plant _and_ till; the haul targeted a building's own tile, which is `blocked` and therefore unpathable; and the ordinary deposit path would intercept a loaded hauler and silently undo the delivery, making the chain look like it was working while nothing ever arrived. A property test caught **two offline over-credits** — an idle factory cannot start until `start + 1`, and a craft must complete strictly inside the gap — and the example tests that encoded the old boundaries were corrected to match the simulation rather than the reverse.

- **Phase 15 — distribution & auto-update** (ADR-025, ADR-028; no schema change; _built; three acceptance criteria open_): the game can update itself, and the design is ADR-025 §1’s precedence rule — **save integrity > update correctness > update speed > update convenience** — applied eighteen times. `ROADMAP.md` §11 planned four commit boundaries; **eighteen shipped, built in the reverse of the planned order**, because §7 says a library that cannot deliver the guarantees is not adopted and that is only a decision anyone can make if the guarantees exist as something executable first. So the rules were written and proven in Node, and `electron-updater` was measured against a test suite rather than against prose. **It delivers one and a half of three.** §5’s restart discipline, yes — but only against its own defaults, since `autoDownload` and `autoInstallOnAppQuit` both ship `true`, which out of the box makes it precisely the silent background updater §Alternatives A rejected, the second racing the quit-save. §2’s schema-bounded rollback, no, and it cannot: the library has no concept of a save, and `allowDowngrade: false` says nothing about whether a **forward** build can read the save on disk, which is the case §Context is actually about. §4’s interruption recovery, not established — it hands off to the NSIS installer, which does not run `install-store.ts`’s retain → swap → commit. The ordering vindicated itself: the policy was proven before the library existed, so every gap already had an answer; had the dependency come first, §2 would have been "configured" with a boolean and the schema hazard would have shipped. That hazard is built entirely out of correct parts — the new build migrates, the player rolls back, the old build meets a `schemaVersion` from the future and refuses it exactly as `SAVE_FORMAT.md` §4.3 says it must, and the farm is unreachable — so the guard moved to the only component that can **prevent** it rather than report it, and it runs on forward updates too: the rule is **a build may be applied only if it can read the save on disk**, and rolling back is one way to violate it rather than the definition of it. **A pin is a ceiling, not a freeze**, and three layers answer three different questions about it on purpose — the IPC boundary asks whether it is the shape of a version, `settings-schema.ts` asks whether the player asked to be held (and therefore **keeps** a pin it cannot parse), and `update-policy.ts` asks whether it can be ordered against a release (and holds when it cannot); sanitizing an unreadable pin at the wrong layer would settle the first question with the second one’s evidence and install a build the player refused. The staged rollout carries no identity: one integer in 0–99 from FNV-1a over the profile path, never transmitted, nothing counted — the concrete contrast with the library’s own `stagingPercentage`, which writes a random id to disk. **Answering "nothing" is evidence; failing to answer is not** — a source returning null withdraws a queued offer so a halt reaches installs that have not taken the build, while a source that rejects changes nothing at all, because a laptop on a train fails that check constantly and treating it as a withdrawal would discard an announcement the player had earned. An offer is announced **once per version, not once per opportunity**, and waits rather than cancelling while the player is hidden or in work mode. `CompanionToast.tsx` stopped being one occupant of a slot and became the slot: a confirmation is a receipt that expires in 2,400 ms and never takes the mouse, an update prompt waits to be dismissed and must take it, and the confirmation wins the slot while it lasts with the prompt returning underneath — losing a prompt behind a hotkey press would silently spend the one announcement §5 allows. The generated `latest.yml` cannot carry `schemaVersion`, `halted`, or a wave meeting §6’s no-stored-identifier rule, so those travel in a small `update-manifest.json` published beside the installer — a separation that is the better shape rather than a workaround, because **halting is then editing one file and re-uploading it**, no rebuild and nothing to sign, which is the only way §6’s "before more installs take it" is cheap enough to use in the minutes after a bad build goes out. Its producer and consumer are tested against each other rather than against fixtures: two fixtures drift, and the drift is invisible in the worst way, since refusing a bad manifest is exactly what the parser is supposed to do — a wrong shape would publish a release every client silently declines with nothing looking broken. `mayDownload` closes the window where the hand-edited manifest and the regenerated feed disagree; in it, the feed’s version is one no guard, pin, or wave has ever seen. **Two findings cost more than the feature.** `TECH_STACK.md` §7.3 had claimed since phase-00 that `npm audit` runs in CI and fails on high advisories; there was no audit step, and it was found by tripping it — adopting `electron-updater` pulled `js-yaml@4.3.0` (GHSA-5p4m-2wfm-xmqj) into the **shipped** tree with nothing objecting. That is phase-08.0’s "documentation wearing a gate’s clothes" in the same document three phases later, fixed 08.0’s way: the gate enforces what it honestly can (`--omit=dev`, clean at zero) and the document now states that the dev tree’s asset-pipeline advisories are **not** gated. The advisory went by resolution rather than exception — `js-yaml@4.3.1` satisfies the library’s own range, so nothing was overridden or waived. And boundary `15h` added the `update` namespace to the preload but not to `src/shared/ipc/global.d.ts`, so the renderer could not name a bridge that existed; nothing failed, because nothing had asked for it yet. **ADR-028 narrows ADR-025 §3 for one milestone**: §3 describes two protections and only the publisher signature needs a certificate, so that is deferred to v0.3 while SHA-512 artifact integrity stays fatal. What is lost is stated in a table rather than softened — the root of trust becomes the release host and TLS — and self-signing is rejected explicitly, because it removes no warning, proves no identity, and turns an honest absence into something that looks like assurance. The exception **expires**: `tests/signing-exception.test.ts` fails at 0.3.0 and goes quiet by itself once any signing key appears, and it was verified by temporarily bumping the version and watching it bite, because a guard nobody has seen fail is a guard nobody knows works.
- **Phase 14 — worker scheduling** (ADR-024; schema **v5 → v6**): the player directs the farm, and the architecture takes zones, roles, shifts and overrides later without being redesigned. Discovery and selection both already existed — `worker-tasks.ts` enumerated candidates and picked the nearest in fixed bands — and what did not exist is the stage between them, which is precisely why the bands could not express **where** or **when**. Adding it is a small diff and a large claim: **every future scheduling concept is a new constraint, not a new stage and not a new code path.** **Absent is unconstrained; empty is impossible**, and the distinction is load-bearing rather than stylistic — "no zone" is a worker who may work anywhere, "an empty zone" is a worker who may work nowhere, and conflating them silently idles a farm. The migration is that one decision: `{}` and not `{ taskKinds: [] }`, because a v5 worker could do anything anywhere at any hour, and the empty-array form would have **silently idled every worker on every existing save**. `exactOptionalPropertyTypes` rejected the conditional-spread hydration and was right to, since the distinction it protects is the one the whole vocabulary rests on. **Priority reorders; it never excludes** (ADR-024 §3): a kind the list does not mention sorts **after** the ones it does rather than being dropped, so a partial ordering is legal and every kind stays reachable — and the reorder is by index rather than by comparator, because an unstable sort would surface as a determinism divergence rather than as a visible misbehaviour. The dependency checker caught a real cycle: putting `WorkerSchedule` in `constraints.ts` made worker **state** depend on its own evaluators, and the fix is not cosmetic — the schedule is state and the predicates over it are AI, and the cycle was that distinction being blurred. A role needed no new mechanism at all, because **a role is a schedule, named**; core ships three, and `core:farmhand` declaring no constraints makes it the identity role rather than a special case. **A role cannot carry a zone**, which is a rule rather than an omission: a zone is a set of tile indices, tile indices are facts about one farm, and a role shipped by a content source that named them would be wrong on every world but the author’s. An unsatisfiable role is refused at **registration**, so the author is told rather than a player later watching a worker stop for no visible reason. The panel dispatches a command rather than writing (ADR-010 §1), and the workers slice gained a `role` — the role a schedule matches, or null for a bespoke one, rendered as "Custom" rather than snapping a dropdown to something the player never chose. Catch-up is bounded by the same schedules: a schedule that forbids the work forbids the credit (ADR-024 §4), asked of the whole crew rather than per worker because the model never decided which worker did a cycle, and "could anyone" is the conservative direction — it credits at most what the real simulation could have produced. Two test mistakes are recorded rather than quietly fixed: a resume case whose zone sat on tile (40, 40), outside the owned 8×8 plot, so the zone was empty for a reason that had nothing to do with scheduling and the test would have passed against a filter stage that did nothing at all; and the round-trip proof, which had to use a **non-default** schedule, because a worker with `{}` round-trips correctly even if the codec drops the field entirely.
- **Phase 13 — audio architecture** (ADR-023; no schema change): the placeholder bus becomes a real architecture. **`HTMLAudioElement` was the right call and stopped being one** — ADR-016 chose an element per sound for good reasons, and ADR-023 §4 changed the requirements rather than the judgement: category buses, declared ducking, per-sound variation, and two instances of one sound overlapping all need a graph, and an element cannot play twice at once at all. The bound moved with it: an element is reusable, a `BufferSourceNode` is single-use, so playing a sound now allocates a node, and an eight-hour farm harvesting continuously is exactly the heap churn ADR-017 §4 forbids for particles. `voice-pool.ts` fixes twelve voices in flight, allocates two typed arrays at construction, and never allocates again; it is arithmetic over slots that knows nothing about Web Audio, which keeps ADR-016 §1's property true — **the interesting part of audio runs in Node with no browser**. Recycling is by CLAIM time rather than end time, so a long sound cannot shield itself from recycling by outlasting everything else; that test had to be written twice, because the first version left one voice already finished and the free-slot scan answered before the tie-break ever ran. Four engine-owned categories (ui, world, ambient, music) sit under the master dial as a **closed** set — an open one makes the mix unpredictable and hands every plugin a way to be the loudest thing on someone's desktop. **Ambience defaults to zero as DATA, not as a check**: ADR-023 §5 condition 1 is expressed as the number in the defaults, so a code path that forgets to check still produces silence. Ducking is a table and a clock, never an analyser — an analyser is a continuously-running signal path, and §5 spends its idle budget on the one continuous thing that earns it. The category getter is optional on `AudioState`, which is what made the change non-breaking: every existing caller kept working and the bus's fourteen Node tests did not change, which is ADR-016 §1's acceptance met rather than asserted. ADR-023 §6's guarantee is now a test — 200 steps of two same-seeded worlds, one with the bus playing throughout, asserting byte-identical saves and rng state. **The coverage gate refused the obvious shortcut and was right to**: the rebuilt device layer went in at 0% and dropped `src/renderer/bootstrap` to 83.24% against its 85% bar, and registering it as a host binding was not permitted, because `TESTING.md` §4.2 requires a host binding to ALSO name a test that exercises it and there is no audio e2e. Phase-08.0 had already answered it — `docking.ts` and `settings.ts` were **parameterised, not mocked** — so `createWebAudioPorts` takes its context factory and loader as options, and a hand-written fake covers lazy construction, decode-once, and all three failure paths: 0% to 87.5%.
- **Phase 12 — weather simulation** (ADR-022; schema **v4 → v5**, the chain's first **removal**): weather is a pure function of `(seed, period, season)` — a hash, **not** a draw from `world.rng`, because consuming the stream would mean a world that displayed weather diverged from one that did not, with the save's determinism hostage to a cosmetic feature. That rule is easy to state and easy to break later, so a test runs 500 derivations between two identical RNG streams and asserts the stream is untouched. The hash moved from `decor.ts` to `shared/hash.ts` rather than being copied: two functions that must agree forever, one of them documented as "any well-mixed integer hash would do", is an invitation to improve one of them and silently change every derived value in every world. **`grid.moisture` was removed** — persisted from v1, serialized, validated, and read by nothing, written for a model ADR-009 deferred and never built — so the link dropped an array of zeros rather than discarding player value, which is the whole test for whether a removal is safe. What replaced it is a different SHAPE, not a rename: `moisture` was a 0–100 level (an accumulator), `wateredAt` is a recorded tick with `tilledAt`'s shape. The migration sizes the new array from the DOCUMENT's own width and height, because a migration describes the save it was handed and a future world-size change must not retro-resize an old farm. Derived wetness sums rainfall over whole weather periods plus two partials, so the eight-hour offline cap is a **96-term sum rather than a 576,000-step loop**, guarded by additivity across arbitrary splits including mid-period ones — if that failed, a tile's wetness would depend on when the player happened to save. Wetness then had to gain a real consumer or not ship at all (ADR-022 §4), and building it **found that the first wetness model was wrong**: `rainfall since wateredAt − drying × elapsed` reads fine and fails after hours, because `wateredAt` is 0 on an untouched tile so rain integrated from the world's first tick and every tile saturated permanently — an accumulator wearing a derivation's clothes, in the phase whose purpose was removing one. A bounded window fixes it by construction. A second defect was worse in kind: `growthProgress` guarded its period length with `length <= 0`, and **`undefined <= 0` is false**, so a source missing the field fell through to a NaN-bounded loop reporting a crop that never grows — four tests failed identically, which is what made it visible rather than looking like a timing shift. Rain accelerates growth by 25% and drought never slows it below the dry rate, so a dry world grows at exactly the speed it grew at before the phase existed and no crop time needed rebalancing; five tests fail if that floor drops. Rain draws on layer 4 asking the SAME presence gate the swaying decor asks, so all four of ADR-017 §2's conditions apply without restatement and the lease cannot disagree with the drawing. **`weatherChanged` was not built**, and ADR-022 §6 carries the amendment. Two test mistakes are recorded rather than quietly fixed: a dry-farm fixture that doctored the weather registry and handed back a **spread copy of the world** — `createWorld` binds its dispatcher to the object it returns, so commands ran against the original while the test inspected the copy — and its replacement, which asserts its own dryness and immediately caught the seed it used raining.
- **Phase 11 — seasonal simulation** (ADR-021; schema **v3 → v4**): the season derives from the day, which derives from the tick — no `seasonSystem`, no `world.season`, no catch-up. The engine owns the CYCLE and content owns the names, so a source can ship a two-season world; there is no `order` field on a season, because registration order already is an order and a second one could disagree with it. **A migration may not read a live registry**: `v3-to-v4` was written first calling `createInstalledRegistries()`, which is wrong in a way that would have hidden for a long time — the same save would migrate to two different worlds on two machines, and the golden fixture meant to catch that would itself vary by environment. The four shipped seasons are a frozen literal, and the mutation control makes the payoff visible: reordering `coreSeasons()` fails the registry test and leaves the migration test untouched. This link **synthesises where `v1 → v2` refused to**, and the distinction is that a v1 save carried no record of its sources so any manifest would have been a claim nobody made, whereas a v3 save carries no seasons because seasons did not exist yet — the test is whether the value was ever ambiguous, not whether it was ever written. Seasons gate what may be **planted**, never what may be kept: a standing crop always matures (ADR-021 §3), and out-of-season folds into the no-seeds branch phase-06b already built, so a worker is never idled by the calendar. Writing the no-deadlock test surfaced that **the out-of-season worker path is reachable only through the seed bin** — without one a worker only ever sows the year-round turnip — and the first version of that test was wrong because it did not know this. The turnip's empty seasons list is therefore load-bearing rather than a tuning gap. Catch-up refuses the WHOLE gap rather than the legal part of it (ADR-021 §5's "where the model cannot be certain it credits nothing"), guarded by the existing never-over property extended to boundary-spanning gaps plus a paired control, without which the rule would be indistinguishable from "no replants across any boundary". A seasonal price modifier joins ADR-013 §4's pipeline — now a product of modifiers floored exactly ONCE, band [0.90, 1.00], never above 1.00 because the base price is the ceiling a player is allowed to memorize — and it reads the crop that YIELDS an item rather than an id that matches it, so a source shipping `mod:melon` yielding `mod:melon_flesh` is not silently unpriced. **`seasonChanged` was not built**; ADR-021 §6 carries the amendment. Two of ADR-021 §2's three declared surfaces shipped: the seasonal harvest-yield modifier is named in the phase doc as left out, because it is the one that most directly reduces what a player gets for work already done. Also recorded: the season-crossing property test first used the eight-hour cap and **stalled `test:coverage` past ten minutes while passing `npm test` in two** — walking into the trap the note directly above it warns about, that V8 instrumentation costs roughly 3.5×.
- **Phase 10 — time simulation** (ADR-020; schema **v2 → v3**): the world has a day, and nothing depends on it — deliberately. Day, time-of-day and phase are **pure functions of `world.tick`**: no new system, no new mutable state, no catch-up, no accuracy contract, because the tick counter is already the accumulator (the ADR-009 §2 precedent applied to time). What v3 adds to the save is not the calendar but its two **inputs** — `ticksPerDay` and the phase set — frozen at world creation, because changing either reinterprets the whole past: halve the day and a player on day 40 is silently on day 80, with every "planted on day 12" memory now wrong. A day is 24,000 ticks (20 real minutes) through four phases — dawn, day, dusk, night. **The simulation publishes a phase and never a fraction of a day**: a `timeOfDay` field would be correct, one line, free to compute, and would republish its slice on all 24,000 ticks, which ADR-005 §2 names a defect outright. Four phases means four republishes, the same move `CropStage` makes for growth. The guarantee is asserted on **both sides of the sim→view boundary** because neither side can see the other's failure — the sim test steps the real tick loop through a full day and expects the slice version to advance by exactly four; the React test counts Profiler commits over the same day and expects four, delivered in hundredths so the store's throttle cannot coalesce two boundaries into one notification. **Layer 5 is claimed**, reserved empty by ADR-001 since phase-02 and filled with no re-layering migration — the payoff `layers.ts` had already recorded for layer 4. The tint is a plain alpha-filled rectangle rather than a blend mode, so ADR-001 §Fallback's canvas backend gets a dimmer night rather than no night; the phase→tint mapping is **registered content**, supplied by `plugins/core` through the public API with no privileged path. Every transition is **finite**: it runs 900 ms, holds one animation lease, and releases it, so the idle state is zero frames by construction rather than by care. That lighting view **stays in the measured coverage set instead of joining the host-binding exclusions** — Pixi's `Graphics` builds geometry without a renderer, so the test drives it against the **real** `createDirtyGate`, making `animationCount()` the same number the render loop consults; ADR-020's "zero rAF across a phase boundary" acceptance is asserted there rather than in an e2e spec, because a boundary is five real minutes away and no fast-forward hook exists. **`dayPhaseChanged` was never built, and ADR-020 §3 now carries the amendment saying so.** Its only named consumer was the lighting view, and by the time that view existed the `time` slice already delivered the phase through the same republish path every other view uses — decisively, a save resuming mid-day _publishes_ but does not _fire_, so an event-driven view would hold its default tint for hours. The ADR's own producer-and-consumer rule is what ruled the event out; it was applied, not waived. **+66 tests (1,968 → 2,034)**, each milestone with a mutation control: publishing a continuous time value fails five tests including both republish counters, and never releasing the animation lease fails six. One of those controls found a **worthless test of my own** — the offline-exactness check passed while `deserialize` dropped `ticksPerDay` entirely, because it was built on a default-length day and the fallback supplied the very value being asserted; rebuilt on a 9,000-tick day it fails under that mutation. **A persisted constant tested at its default is not tested at all**, which is now recorded for the two remaining ADR-027 links that add one. A mutation control in 10a also exposed a **documentation** defect rather than a code one: a comment claimed `PHASE_STARTS[0]` "MUST be 0" when `phaseFor` walks backwards and never reads index 0 at all.
- **Phase 09 — plugin loader & capability registry** (ADR-019, ADR-026, ADR-027; schema **v1 → v2**): a third party can add content without touching engine source. One sentence from ADR-019 §6 governs almost every decision — _a failure refuses exactly one source, names it, and leaves the rest loaded_ — so every layer is **total**: each directory comes back installed or refused with a reason, and the reason survives all the way to a panel the player can read. **A contested namespace refuses every claimant**, resolving a conflict between `plugins/manifest.schema.json` (reject both) and `ROADMAP.md` §5 (refuse one) in the schema's favour, because it is the contract authors write against and because picking a winner needs a rule for who is first: ordering by id decides whose content survives by alphabet, ordering by install time makes a save load differently tomorrow. Version ranges are **refused rather than guessed** — `*`, an exact version and `^x.y.z` are understood, while `>=1.0.0`, `~1.2.3` and `1.x` are refused by name, because a range the engine misreads surfaces later as content that is simply not there. The `v1 → v2` migration **invents nothing**: `world.sources` migrates to the empty manifest rather than a synthesised `core` entry, because every v1 save WAS written by a build with core content, so the invented entry would look right and would be a lie; and `disabledSources` records what is OFF rather than what is on, so an `enabled: []` default cannot silently disable core on every v1 save ever written. The pre-migration backup's exemption from pruning is **structural** rather than a rule someone must remember — its filename cannot match `pruneBackups`'s filter, and a test pins the two against each other. **Path traversal was a real vulnerability**, found and closed while writing the file-reading code: definition paths come from a downloaded manifest and `readFileSync` will follow `../../../` out of the plugins directory; a declared path must now resolve inside the source, and an absolute path is refused. Only `crops` and `items` are admitted, and an unknown kind is **refused rather than ignored**, so an author who writes `"buildings"` is told instead of watching it vanish. Two defects found by this phase's work were fixed on the way: the catch-up over-credit (`phase-07.7` debt #13) and the unpinned seeds guarding it (#14).
- **Phase 08 — content identity & plugin foundation** (ADR-019, ADR-026; no schema change): closes ADR-003 §6's gap, which had been unbacked since phase-00 — _"the API is proven sufficient by first-party content before any third party depends on it"_ was a claim about a `PluginApi` that did not exist in the repository. `plugins/core/` now registers every core definition through the public API and nothing else: no privileged path, no internal shortcut, no capability reachable from there that a third-party source cannot reach, which is what keeps ADR-026 §2's "the engine never branches on provenance" true at the one seam where it matters most. The four `registerCore*` bodies were moved **by script**, so no value could drift. A namespace is owned by exactly one source permanently, a collision refuses both claimants, and reserved namespaces are refused to third parties. The `sim ↛ plugins` constraint was resolved with an **ambient installed-source registry** — a module-level registry that lets `createWorld` receive content without the simulation importing plugins. `tests/provenance-blindness.test.ts` greps comment-stripped code so `src/sim` cannot read provenance at all, and `src/persistence` cannot BRANCH on it, which is the honest rule: ADR-026 §4 requires the save to record provenance, so a blanket ban there would have been unimplementable. Byte-identical saves were **proven by measurement** rather than asserted — sha256 `f8e920f5…c380`, 34,158 bytes, before and after the migration. One find worth keeping: `core:wheat` is both a crop id and an item id, so the API's duplicate check keys on `kind:id` — uniqueness is per registry, never across a bundle.

- **v0.2 Phase 0 — architecture refresh & roadmap** (docs only, no runtime change): the design phase that turns a finished application into an extensible engine. All eighteen existing ADRs reviewed against ten architectural goals; **none required replacement** — six get successor ADRs, one (ADR-009) constrains without changing, and eleven stand unamended. Nine new ADRs. **ADR-026 (content identity)** is the foundation and was not in the original brief: designing save compatibility around _plugins_ specifically would make official packs, generated packs, and DLC either special cases or lies, so one identity model covers all five kinds — a namespace is owned by exactly one source, a source declares a provenance the engine **records and never branches on**, and one isolation invariant replaces two adjacent rules: _removing a content source may affect only entities, containers, side-tables, and partitions in namespaces that source owns; nothing else in the save may change._ **ADR-019 (plugin architecture)** makes the API an explicitly versioned public contract — compatibility declared against `PLUGIN_API_VERSION`, never the engine version, because engine releases move for reasons no plugin can observe. The full capability surface is specified; **v1 declares the subset that executes no plugin code**, since `script-src 'self'` has no `unsafe-eval` and ADR-001 recorded that the CSP stayed strict _specifically because_ plugins run in the renderer — so determinism and save safety are structural rather than promised. Commands, listeners, panels, and services are API v2, with the four questions a successor ADR must answer named rather than stubbed. **ADR-020/021/022** discovered that the day, the season, the weather, and tile wetness are all **derivations, not systems** — v0.2 adds nothing to `TICK_SYSTEMS`, and ADR-022 §2 makes that the detector: if weather needs a tick slot, the design is wrong. Because weather is a pure function of `(seed, period, season)`, rainfall over any span decomposes into whole periods — **a piecewise-constant rate history that never had to be stored**, which is the second mechanism ADR-009 §2 named, obtained for free, so weather-modulated growth becomes possible with no accumulator and no error budget. **ADR-024** replaces "worker priorities" with a three-stage scheduling pipeline, because a reorderable list answers one of six roadmap concepts and turns the other five into special cases — including emergency override, which would have arrived as the privileged write path ADR-010 §6 exists to forbid. **ADR-023** answers the ambient-audio question ADR-016 §4 deferred, with five conditions and a measured budget as the gate. **ADR-025** found that **rollback across a schema bump orphans a save** — every component behaving correctly, composing into data loss — and bounds rollback by schema version. **ADR-027** answers ADR-015's Open Question 1: pre-migration backups kept indefinitely, because ADR-025 makes them the only recovery path rather than insurance.

- ADR-018, developer tooling and debug architecture (decided ahead of phase-07.8): formalises the rules phase-01.5 followed by convention and never wrote down, at the moment phase-07.8 will roughly quadruple the tooling surface and add the first tools that **write** to the world. Ten decisions, of which three matter most because they erode silently. **Debug tools never mutate simulation state directly** — spawn, remove and reset submit commands through the ordinary player source and are validated and rejectable like any other (ADR-010 §6), which buys replayability, rejectability, and the property that a bug reproduced with debug tools is a real reproduction; the console's existing `money` command is the model. **Tooling consumes events and never produces them**, because a debug-produced event would make the event graph differ between builds and a bug depending on event ordering would stop reproducing in the only build equipped to diagnose it. **Debug rendering obeys render-on-demand** — a closed overlay costs nothing and an open one takes an animation lease like anything else that moves (ADR-017 §1), with live graphs called out as the trap: a 60-second history repainting at 60 Hz makes the thing it measures worse and its own readings untrustworthy. `FEATURE_DEBUG` is confirmed as the single compile-time gate, sub-flags may refine a debug build but none may re-enable tooling in a release, and removal stays asserted against a real built artifact rather than against the source. - Performance validation and instrumentation (phase-07.7M — **the three open budgets, measured**): the tick budget in `PERFORMANCE.md` is stated as a **p99** and nothing in this project could measure one — the loop reported a rolling ticks-per-second, which is an average and hides exactly the tail a p99 exists to expose, so "p99 tick unchanged" had never been a checkable claim. A duration histogram now keeps a ring of the last 4,096 samples (rather than bucketed counts, which answer with a bucket edge when the question is whether a budget was met), records allocation-free into a pre-allocated array, and is **absent from production by construction** — `FEATURE_PROFILER` is a compile-time literal, so a release build takes the loop's un-instrumented branch and Rollup drops the module. A repeatable harness (`tests/e2e/perf-harness.spec.ts`) measures against a real window and writes every result to `docs/perf/*.json`, so a number quoted in a document has a file behind it rather than a memory of a run. **Criterion 5: 0.100 ms p99 against a 3 ms budget** over 1,287 batches — recorded honestly, since `performance.now()` is coarsened to 0.1 ms here, so the 0.000 ms p50 means _below the clock's resolution_ rather than _instant_. **Criterion 8: 100 FPS with one animation lease while the pointer is active, 0 FPS with 0 leases after 14 s untouched** — ADR-017 §2 condition 4 proven end to end rather than argued, and the measurement that makes the ambient-motion exception legitimate instead of a hole in ADR-001; it could not be taken until 07.7L made the setting reachable. **Criterion 11: 3.2 MB heap growth over 30 minutes at 99.7% active, against a 25 MB ceiling** — and the shape matters more than the number: flat for twenty minutes, one step, flat for ten, which is a one-time allocation rather than the progressive growth a leak produces, so the linear extrapolation to ~51 MB over eight hours would be wrong. **The first 30-minute soak was invalid and is kept as evidence**: it moved the pointer once per five-second sample, the IPC metric reads pushed the gap past the 8 s presence timeout, and **66% of it ran idle** — measuring the cheap state the test exists to avoid while reporting a confident 0.00 MB. Nothing in the output looked wrong; it was caught by checking the animation column rather than trusting the number. The harness now reports `activeShare` and asserts it exceeds 0.8. Two limitations are documented rather than smoothed over: `performance.memory` is quantised (two distinct values across 298 samples), so growth is bounded below its bucket size but not shown byte-stable — CDP `Runtime.getHeapUsage` is the recorded improvement — and these figures come from a 28-core desktop, making them a ceiling check rather than a floor. **No optimisation was performed**, because nothing exceeded a budget. - Game feel (phase-07.7, ADR-017 — **the farm responds to being touched**): tilling throws dust, a seed presses in, a growth stage swells and sparkles, a harvest lifts and fades while leaves scatter and a `+n` rises, a sale bursts gold at the market stall, and workers ease into their steps and finally **swing while they work**. Motion is now one of two classes. Finite effects acquire an animation lease, run, and release, so they cost nothing at idle and default ON. Ambient motion defaults OFF, never runs collapsed or in work mode, and **surrenders the frame loop when the pointer has been idle for eight seconds** — which restates ADR-001's invariant rather than repealing it: when the world is static _and_ the player is absent, no frame is drawn. `bindAnimationLease` makes the lease structural instead of a habit, since `dirty-gate` calls its animation count "the fragile half", two call sites carried that bookkeeping by hand, and this phase would otherwise have added five more. Camera shake ships **off** and is asserted to return to exactly zero, since a shake ending a fraction of a pixel off displaces the camera permanently and a hundred of them accumulate. HUD feel is CSS transitions on compositor properties, so React never re-renders for it — and the game's own Reduced Motion switch now reaches CSS at all, which it previously did not. **Fourteen named effects were refused with stated reasons** rather than faked: scratch-head and sit need pose art that does not exist; worker-step is an ambient bed with extra steps; button-hover fires while the player is reaching for another window; grass sway would mean re-rendering baked terrain chunks every frame; and no windmill, chimney, or flag exists to animate. **Not complete:** the six accessibility settings gate every effect correctly but have **no user interface** — they are reachable only by hand-editing `settings.json` — and the p99 tick and 30-minute heap budgets are unmeasured.
- Autosave, the return summary, and the phase-07 close (phase-07e — **the game now saves itself**): every trigger `SAVE_FORMAT.md` §7.2 names is live — the 60-second cadence, quit (which **blocks shutdown**, capped at 3 s so a wedged renderer can delay it but never prevent it), close-to-tray (quick hide, this overlay's only true absence), major transactions, and a manual button in settings. Triggers live in the main process and the document lives in the renderer, so every one of them becomes the same `save:requested` event and there is still exactly one serialization site. The cadence derives its period from `AUTOSAVE_INTERVAL_TICKS` rather than restating "60 s", so the wall-clock timer main needs cannot drift from the tick constant. **Coalescing lives only in the renderer**, the one side that can see a write in flight: one write at a time, and a burst during it collapses to a single follow-up — collapsed, not dropped, because the trigger that lands mid-write is often the quit save. Serialization is deferred out of the frame that asked for it, since the transaction trigger fires from a snapshot subscriber inside `store.pump`. Major transactions are read from the **snapshot** rather than the command stream: a command can be submitted and rejected, but a slice only changes when the world did. The §9.4 **return summary** reports time away, harvests, coins earned, and what blocked progress ("Storage full after 2h 14m"), dismissible and never modal — and **defers in work mode rather than vanishing** (ADR-014's stated requirement, the reason work mode had to ship before phase-07): the controller holds the report while the HUD is hidden, so leaving work mode shows what the player never got to read. A **save failure** carries the path — only main knows it, and the renderer never derives one — persists instead of auto-dismissing, clears itself when a later save succeeds, and shows in work mode too, because withholding "your game is not being saved" to keep the desktop quiet is misleading rather than quiet. ### Fixed

- **Collapsing the overlay and expanding it again left the world black** (reported from play, after the v0.3 RC was written). Reproduced deterministically: the renderer came back sized to the **collapsed** window (1920×48) inside the expanded one (1920×220), so everything below the status bar was empty. Root cause is one shape with two faces — the world is built asynchronously while the window it is being built for keeps changing. Collapse state is applied optimistically in the renderer (the UI must never wait on IPC) and main resizes the window a moment later, so **every** expand starts its build against the collapsed window; the resize that follows arrives while the build is still awaiting the GPU, where `resize` has no view to forward it to and drops it, and nothing reconciled afterwards. The build now re-reads the viewport once the view exists — a resize landing after that point finds a live view, so between the two every ordering is covered. The same investigation exposed the second face, which the file's own comment claimed was handled and was not: a collapse arriving mid-build left the finished view **adopted and alive**, a GPU context burning behind a status bar, which is exactly what ADR-001 §2 destroys the application to avoid; the build now discards its own result when it resolves unwanted, before input is ever attached. The seam had **no unit test at all**, which is how both lived here unseen — it has five now, plus an end-to-end test that performs the player's actual gesture (the far-right chevron, twice) and asserts the world canvas matches the window it is supposed to fill. That test fails on the old code with exactly the reported symptom. Worth recording beside the v0.3 RC's own lesson: the release gates were all green over this bug, because collapse/expand had **window** geometry coverage and GPU-gated leak coverage, and nothing asserted that the thing inside the window matches the window.

- **Catch-up over-credited a shift-constrained crew** (ADR-024 §4, found by phase 14’s verification pass). `anyWorkerMayWork` asked `phaseFor(world.tick)` — **one** day phase — and applied the answer to a catch-up window of up to eight hours, so a crew on shift for one phase in four was credited exactly what an unconstrained crew earned. It survived four tests because every one of them constrained by **zone or task kind**, and neither changes with the clock: evaluating those once is correct, so the tests were right about what they covered and silent about what they did not. The correct shape was already in the same function — `plantableThroughout` asks `seasonsBetween` for every season a window touches — so `phasesBetween` is now its counterpart, named to match, and permission is required **throughout** the window. "Throughout" is asked per worker rather than per phase: crediting a cycle needs one worker who could have done it for the whole window, not a relay who each could have done part, because the model never decided which worker did a cycle. The fix is conservative — a partially-on-shift crew is credited nothing rather than a share — which is acceptable today because **no shipped role declares a shift**; the field exists and core’s three roles constrain task kinds only, so this bounds a future shift correctly and changes nothing a player can reach. A proportional share is the better answer once a role declares one, and is a change to make with that role in hand.
- Non-deterministic test count: the headless import suite enumerated `src/sim` at collection time and picked up the temporary fixtures `boundaries.test.ts` writes into `src/sim/__boundary_fixtures__/` from a parallel worker, so identical runs reported different totals. Transient `__`-prefixed directories are now excluded from enumeration.

## Versioning Rules

### Two version numbers

This project tracks **two independent versions**. Confusing them causes save-compatibility bugs.

| Version                 | Format                  | Meaning                     | Where                                   |
| ----------------------- | ----------------------- | --------------------------- | --------------------------------------- |
| **App version**         | Semantic (`0.1.0`)      | The release the player sees | `package.json`, `meta.gameVersion`      |
| **Save schema version** | Integer (`1`, `2`, `3`) | The persisted data format   | `schemaVersion` (`SAVE_FORMAT.md` §4.1) |

They move independently. A patch release may bump the schema; a minor release may not. **Only `schemaVersion` controls migration** — `meta.gameVersion` is informational and must never drive logic (`SAVE_FORMAT.md` §2.1).

### Semantic versioning, as applied here

Pre-1.0, the conventional rules are adapted to the roadmap in `PLAN.md`:

| Bump                | Means                                               | Example         |
| ------------------- | --------------------------------------------------- | --------------- |
| **MAJOR** (`1.0.0`) | v1.0 — the feature-complete life simulator          | Reserved        |
| **MINOR** (`0.2.0`) | A roadmap tier: new systems, possibly a schema bump | v0.1 → v0.2     |
| **PATCH** (`0.1.1`) | Fixes, balance, performance; no new systems         | Bug fix release |

**Backward compatibility is never broken**, at any bump (`AI_RULES.md` §1.4). A v0.1 save must load in v1.0. There is no version increment that licenses breaking a save.

## Entry Format

### Categories

Use these six, in this order. Omit empty ones.

| Category     | For                          |
| ------------ | ---------------------------- |
| `Added`      | New features                 |
| `Changed`    | Changes to existing behavior |
| `Deprecated` | Features to be removed later |
| `Removed`    | Features removed now         |
| `Fixed`      | Bug fixes                    |
| `Security`   | Vulnerability fixes          |

### Writing entries

Entries are for **players**, not developers. The reader wants to know what changed about the game, not which module was refactored.

```markdown
## [0.2.0] - 2026-XX-XX

### Added

- Weather system: rain automatically waters crops
- Plugin loader — mods can now add crops, items, and buildings
- Day/night cycle affecting worker schedules

### Changed

- Wheat growth time reduced from 120s to 100s
- Market Stall now sells at 92% (was 90%)

### Fixed

- Workers no longer stall when storage fills while carrying items
- Overlay re-docks correctly after a DPI change

### Save Compatibility

- Schema version 1 → 2 (adds weather state)
- v0.1 saves load automatically; no player action needed
```

### The Save Compatibility section

**Required on any release that bumps `schemaVersion`.** It must state the version transition and, in plain language, what the player needs to do — normally "nothing."

This section exists because save compatibility is the promise this project makes most seriously, and a release that changes the format without saying so undermines it even when the migration works.

### Rules

- **Player-facing language.** "Workers no longer stall when storage fills," not "fixed null deref in `deposit-task.ts`."
- **No internal refactors.** If it does not change what the player experiences, it does not belong here (that is what git history is for).
- **One line per change.** Link to an issue if there is detail worth having.
- **Add to `[Unreleased]` in the same commit as the change** (`AI_RULES.md` §5.4).
- **Balance changes are always listed.** A player who notices wheat is faster deserves to find it here.
- **Performance improvements are listed when measurable**, with the measurement: "Idle CPU reduced from 1.4% to 0.6%."

## Release Process

1. Verify every gate in `PLAN.md` §8 — **including zero known data-loss defects**
2. Move `[Unreleased]` entries under a new version heading with the release date
3. Add the Save Compatibility section if `schemaVersion` changed
4. Bump `version` in `package.json`
5. Confirm every golden fixture still loads (`SAVE_FORMAT.md` §4.4)
6. Tag the release `v<version>`
7. Create a fresh empty `[Unreleased]` section

Step 5 is not optional and not covered by step 1's general test run. It is the specific check that a released build can still load saves from every prior version.
