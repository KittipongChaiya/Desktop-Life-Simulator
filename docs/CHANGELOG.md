## [Unreleased]

### Added

- **Phase 18 — settlement** (ADR-030; schema **v6 → v7**, the chain's first **relayout**): the world widens one chunk column east — 64×64 becomes 80×64 — and a village stands on the new land: four cottages around a plaza, a well at its centre, a notice board by the road for phase-20's contracts, and a castle (the owner's addition) looking down from the north. **The farm is pinned west by meaning, not coincidence**: the starting plot centres in the FARM region, `expandLand` caps at `FARM_SIZE`, and a new worker spawns at the farm centre — so every existing tile keeps its coordinates forever and ownership can never cross into town land, which is the entire access-control model (a town tile is simply never owned, so every ownership-gated command already refuses it). The migration re-lays four dense grid arrays (the bitfield bit by bit) and remaps every stored tile index by pure arithmetic — a thing at (x, y) before the link is at (x, y) after it, asserted in coordinates — and adds **nothing**, because migrations transform shape and a town is not a shape. The town arrives by construction instead: `foundTown` is one idempotent code path run by `createWorld` for a new world and by hydration (after restore, so ids never collide) for a loaded one, so **a migrated v0.2 farm gains its neighbours on first load** and a v0.3 save keeps exactly what it has. The guard's soundness got enforced on the way: `sellBuilding` previously validated only existence, so the town well was refundable to anyone who asked — it now requires the building to stand on owned land, which forbids nothing a player could ever legitimately do. Three lessons cost their own tests: the quarantine remap passed **vacuously** (every golden fixture carries an empty quarantine, so an undefined helper survived until the type checker caught it — a populated-quarantine test now exists); the village's arrival broke four e2e save specs because the **major-transaction watcher baselined on the empty pre-pump store** and counted seven founded buildings as a purchase, firing a save seconds into every fresh launch (it now baselines on the world's first delivery — a world announcing itself is not a transaction); and criterion 12 failed once with the ambient bed still on after the away wait because **a real mouse crossed the test window** — somebody was at the machine, so absence could not be measured, and the criterion now counts away-window pointer events and skips as environment-blocked when they exist. Sprites are scripted painters like all the art before them — the cottage a steep chimneyed gable, the well the only circular building read, the board paper-on-wood, the castle the tallest stone silhouette held cozy per "nothing threatens home". Re-measured against the phase-17 baseline with the village standing: p99 tick 0.4 ms vs 0.5 ms — inside the clock's coarsening, honestly "unchanged". No renderer changes were needed to draw any of it, which is ADR-004 §5 paying out.
- **Phase 17 — v0.3 baseline** (no schema change): the two v0.2 leftovers that were code rather than money, closed with evidence. The coverage gate re-ran clean on a quiet machine — 2,567/2,567 tests, 95.07% lines / 86.56% branches — confirming the stalls were contention. And the combined budget run phase-16 named as the one open measurement was taken: criterion 12 plants the reference farm stepped to the start of a **derived** rain period (weather is a hash, so the search is arithmetic) and measures with weather, lighting, audio, and every motion class live at once — p99 tick 0.5 ms against the 3 ms budget, and the ambient bed still surrenders on idle **while it is still raining**, so "off" can only mean presence expired. Its first execution failed usefully: 100 FPS with the pointer away, because workers farm unwatched and every harvest re-arms a transient animator faster than the last one finishes. Not a defect — render-on-demand drawing a world that genuinely changes — but it means **"expanded idle" does not occur on a mature farm**, the v0.3 entity budget must profile against expanded-and-unattended, and whether gameplay-feedback animators should be presence-gated is now an open design question with data behind it, assigned to the NPC work. Signing (a purchase) and the three update paths (need a published release) stay parked with owners.

- **Phase 15 — distribution & auto-update** (ADR-025, ADR-028; no schema change; _built; three acceptance criteria open_): the game can update itself, and the design is ADR-025 §1’s precedence rule — **save integrity > update correctness > update speed > update convenience** — applied eighteen times. `ROADMAP.md` §11 planned four commit boundaries; **eighteen shipped, built in the reverse of the planned order**, because §7 says a library that cannot deliver the guarantees is not adopted and that is only a decision anyone can make if the guarantees exist as something executable first. So the rules were written and proven in Node, and `electron-updater` was measured against a test suite rather than against prose. **It delivers one and a half of three.** §5’s restart discipline, yes — but only against its own defaults, since `autoDownload` and `autoInstallOnAppQuit` both ship `true`, which out of the box makes it precisely the silent background updater §Alternatives A rejected, the second racing the quit-save. §2’s schema-bounded rollback, no, and it cannot: the library has no concept of a save, and `allowDowngrade: false` says nothing about whether a **forward** build can read the save on disk, which is the case §Context is actually about. §4’s interruption recovery, not established — it hands off to the NSIS installer, which does not run `install-store.ts`’s retain → swap → commit. The ordering vindicated itself: the policy was proven before the library existed, so every gap already had an answer; had the dependency come first, §2 would have been "configured" with a boolean and the schema hazard would have shipped. That hazard is built entirely out of correct parts — the new build migrates, the player rolls back, the old build meets a `schemaVersion` from the future and refuses it exactly as `SAVE_FORMAT.md` §4.3 says it must, and the farm is unreachable — so the guard moved to the only component that can **prevent** it rather than report it, and it runs on forward updates too: the rule is **a build may be applied only if it can read the save on disk**, and rolling back is one way to violate it rather than the definition of it. **A pin is a ceiling, not a freeze**, and three layers answer three different questions about it on purpose — the IPC boundary asks whether it is the shape of a version, `settings-schema.ts` asks whether the player asked to be held (and therefore **keeps** a pin it cannot parse), and `update-policy.ts` asks whether it can be ordered against a release (and holds when it cannot); sanitizing an unreadable pin at the wrong layer would settle the first question with the second one’s evidence and install a build the player refused. The staged rollout carries no identity: one integer in 0–99 from FNV-1a over the profile path, never transmitted, nothing counted — the concrete contrast with the library’s own `stagingPercentage`, which writes a random id to disk. **Answering "nothing" is evidence; failing to answer is not** — a source returning null withdraws a queued offer so a halt reaches installs that have not taken the build, while a source that rejects changes nothing at all, because a laptop on a train fails that check constantly and treating it as a withdrawal would discard an announcement the player had earned. An offer is announced **once per version, not once per opportunity**, and waits rather than cancelling while the player is hidden or in work mode. `CompanionToast.tsx` stopped being one occupant of a slot and became the slot: a confirmation is a receipt that expires in 2,400 ms and never takes the mouse, an update prompt waits to be dismissed and must take it, and the confirmation wins the slot while it lasts with the prompt returning underneath — losing a prompt behind a hotkey press would silently spend the one announcement §5 allows. The generated `latest.yml` cannot carry `schemaVersion`, `halted`, or a wave meeting §6’s no-stored-identifier rule, so those travel in a small `update-manifest.json` published beside the installer — a separation that is the better shape rather than a workaround, because **halting is then editing one file and re-uploading it**, no rebuild and nothing to sign, which is the only way §6’s "before more installs take it" is cheap enough to use in the minutes after a bad build goes out. Its producer and consumer are tested against each other rather than against fixtures: two fixtures drift, and the drift is invisible in the worst way, since refusing a bad manifest is exactly what the parser is supposed to do — a wrong shape would publish a release every client silently declines with nothing looking broken. `mayDownload` closes the window where the hand-edited manifest and the regenerated feed disagree; in it, the feed’s version is one no guard, pin, or wave has ever seen. **Two findings cost more than the feature.** `TECH_STACK.md` §7.3 had claimed since phase-00 that `npm audit` runs in CI and fails on high advisories; there was no audit step, and it was found by tripping it — adopting `electron-updater` pulled `js-yaml@4.3.0` (GHSA-5p4m-2wfm-xmqj) into the **shipped** tree with nothing objecting. That is phase-08.0’s "documentation wearing a gate’s clothes" in the same document three phases later, fixed 08.0’s way: the gate enforces what it honestly can (`--omit=dev`, clean at zero) and the document now states that the dev tree’s asset-pipeline advisories are **not** gated. The advisory went by resolution rather than exception — `js-yaml@4.3.1` satisfies the library’s own range, so nothing was overridden or waived. And boundary `15h` added the `update` namespace to the preload but not to `src/shared/ipc/global.d.ts`, so the renderer could not name a bridge that existed; nothing failed, because nothing had asked for it yet. **ADR-028 narrows ADR-025 §3 for one milestone**: §3 describes two protections and only the publisher signature needs a certificate, so that is deferred to v0.3 while SHA-512 artifact integrity stays fatal. What is lost is stated in a table rather than softened — the root of trust becomes the release host and TLS — and self-signing is rejected explicitly, because it removes no warning, proves no identity, and turns an honest absence into something that looks like assurance. The exception **expires**: `tests/signing-exception.test.ts` fails at 0.3.0 and goes quiet by itself once any signing key appears, and it was verified by temporarily bumping the version and watching it bite, because a guard nobody has seen fail is a guard nobody knows works.
- **Phase 14 — worker scheduling** (ADR-024; schema **v5 → v6**): the player directs the farm, and the architecture takes zones, roles, shifts and overrides later without being redesigned. Discovery and selection both already existed — `worker-tasks.ts` enumerated candidates and picked the nearest in fixed bands — and what did not exist is the stage between them, which is precisely why the bands could not express **where** or **when**. Adding it is a small diff and a large claim: **every future scheduling concept is a new constraint, not a new stage and not a new code path.** **Absent is unconstrained; empty is impossible**, and the distinction is load-bearing rather than stylistic — "no zone" is a worker who may work anywhere, "an empty zone" is a worker who may work nowhere, and conflating them silently idles a farm. The migration is that one decision: `{}` and not `{ taskKinds: [] }`, because a v5 worker could do anything anywhere at any hour, and the empty-array form would have **silently idled every worker on every existing save**. `exactOptionalPropertyTypes` rejected the conditional-spread hydration and was right to, since the distinction it protects is the one the whole vocabulary rests on. **Priority reorders; it never excludes** (ADR-024 §3): a kind the list does not mention sorts **after** the ones it does rather than being dropped, so a partial ordering is legal and every kind stays reachable — and the reorder is by index rather than by comparator, because an unstable sort would surface as a determinism divergence rather than as a visible misbehaviour. The dependency checker caught a real cycle: putting `WorkerSchedule` in `constraints.ts` made worker **state** depend on its own evaluators, and the fix is not cosmetic — the schedule is state and the predicates over it are AI, and the cycle was that distinction being blurred. A role needed no new mechanism at all, because **a role is a schedule, named**; core ships three, and `core:farmhand` declaring no constraints makes it the identity role rather than a special case. **A role cannot carry a zone**, which is a rule rather than an omission: a zone is a set of tile indices, tile indices are facts about one farm, and a role shipped by a content source that named them would be wrong on every world but the author’s. An unsatisfiable role is refused at **registration**, so the author is told rather than a player later watching a worker stop for no visible reason. The panel dispatches a command rather than writing (ADR-010 §1), and the workers slice gained a `role` — the role a schedule matches, or null for a bespoke one, rendered as "Custom" rather than snapping a dropdown to something the player never chose. Catch-up is bounded by the same schedules: a schedule that forbids the work forbids the credit (ADR-024 §4), asked of the whole crew rather than per worker because the model never decided which worker did a cycle, and "could anyone" is the conservative direction — it credits at most what the real simulation could have produced. Two test mistakes are recorded rather than quietly fixed: a resume case whose zone sat on tile (40, 40), outside the owned 8×8 plot, so the zone was empty for a reason that had nothing to do with scheduling and the test would have passed against a filter stage that did nothing at all; and the round-trip proof, which had to use a **non-default** schedule, because a worker with `{}` round-trips correctly even if the codec drops the field entirely.
- **Phase 13 — audio architecture** (ADR-023; no schema change): the placeholder bus becomes a real architecture. **`HTMLAudioElement` was the right call and stopped being one** — ADR-016 chose an element per sound for good reasons, and ADR-023 §4 changed the requirements rather than the judgement: category buses, declared ducking, per-sound variation, and two instances of one sound overlapping all need a graph, and an element cannot play twice at once at all. The bound moved with it: an element is reusable, a `BufferSourceNode` is single-use, so playing a sound now allocates a node, and an eight-hour farm harvesting continuously is exactly the heap churn ADR-017 §4 forbids for particles. `voice-pool.ts` fixes twelve voices in flight, allocates two typed arrays at construction, and never allocates again; it is arithmetic over slots that knows nothing about Web Audio, which keeps ADR-016 §1's property true — **the interesting part of audio runs in Node with no browser**. Recycling is by CLAIM time rather than end time, so a long sound cannot shield itself from recycling by outlasting everything else; that test had to be written twice, because the first version left one voice already finished and the free-slot scan answered before the tie-break ever ran. Four engine-owned categories (ui, world, ambient, music) sit under the master dial as a **closed** set — an open one makes the mix unpredictable and hands every plugin a way to be the loudest thing on someone's desktop. **Ambience defaults to zero as DATA, not as a check**: ADR-023 §5 condition 1 is expressed as the number in the defaults, so a code path that forgets to check still produces silence. Ducking is a table and a clock, never an analyser — an analyser is a continuously-running signal path, and §5 spends its idle budget on the one continuous thing that earns it. The category getter is optional on `AudioState`, which is what made the change non-breaking: every existing caller kept working and the bus's fourteen Node tests did not change, which is ADR-016 §1's acceptance met rather than asserted. ADR-023 §6's guarantee is now a test — 200 steps of two same-seeded worlds, one with the bus playing throughout, asserting byte-identical saves and rng state. **The coverage gate refused the obvious shortcut and was right to**: the rebuilt device layer went in at 0% and dropped `src/renderer/bootstrap` to 83.24% against its 85% bar, and registering it as a host binding was not permitted, because `TESTING.md` §4.2 requires a host binding to ALSO name a test that exercises it and there is no audio e2e. Phase-08.0 had already answered it — `docking.ts` and `settings.ts` were **parameterised, not mocked** — so `createWebAudioPorts` takes its context factory and loader as options, and a hand-written fake covers lazy construction, decode-once, and all three failure paths: 0% to 87.5%.
- **Phase 12 — weather simulation** (ADR-022; schema **v4 → v5**, the chain's first **removal**): weather is a pure function of `(seed, period, season)` — a hash, **not** a draw from `world.rng`, because consuming the stream would mean a world that displayed weather diverged from one that did not, with the save's determinism hostage to a cosmetic feature. That rule is easy to state and easy to break later, so a test runs 500 derivations between two identical RNG streams and asserts the stream is untouched. The hash moved from `decor.ts` to `shared/hash.ts` rather than being copied: two functions that must agree forever, one of them documented as "any well-mixed integer hash would do", is an invitation to improve one of them and silently change every derived value in every world. **`grid.moisture` was removed** — persisted from v1, serialized, validated, and read by nothing, written for a model ADR-009 deferred and never built — so the link dropped an array of zeros rather than discarding player value, which is the whole test for whether a removal is safe. What replaced it is a different SHAPE, not a rename: `moisture` was a 0–100 level (an accumulator), `wateredAt` is a recorded tick with `tilledAt`'s shape. The migration sizes the new array from the DOCUMENT's own width and height, because a migration describes the save it was handed and a future world-size change must not retro-resize an old farm. Derived wetness sums rainfall over whole weather periods plus two partials, so the eight-hour offline cap is a **96-term sum rather than a 576,000-step loop**, guarded by additivity across arbitrary splits including mid-period ones — if that failed, a tile's wetness would depend on when the player happened to save. Wetness then had to gain a real consumer or not ship at all (ADR-022 §4), and building it **found that the first wetness model was wrong**: `rainfall since wateredAt − drying × elapsed` reads fine and fails after hours, because `wateredAt` is 0 on an untouched tile so rain integrated from the world's first tick and every tile saturated permanently — an accumulator wearing a derivation's clothes, in the phase whose purpose was removing one. A bounded window fixes it by construction. A second defect was worse in kind: `growthProgress` guarded its period length with `length <= 0`, and **`undefined <= 0` is false**, so a source missing the field fell through to a NaN-bounded loop reporting a crop that never grows — four tests failed identically, which is what made it visible rather than looking like a timing shift. Rain accelerates growth by 25% and drought never slows it below the dry rate, so a dry world grows at exactly the speed it grew at before the phase existed and no crop time needed rebalancing; five tests fail if that floor drops. Rain draws on layer 4 asking the SAME presence gate the swaying decor asks, so all four of ADR-017 §2's conditions apply without restatement and the lease cannot disagree with the drawing. **`weatherChanged` was not built**, and ADR-022 §6 carries the amendment. Two test mistakes are recorded rather than quietly fixed: a dry-farm fixture that doctored the weather registry and handed back a **spread copy of the world** — `createWorld` binds its dispatcher to the object it returns, so commands ran against the original while the test inspected the copy — and its replacement, which asserts its own dryness and immediately caught the seed it used raining.
- **Phase 11 — seasonal simulation** (ADR-021; schema **v3 → v4**): the season derives from the day, which derives from the tick — no `seasonSystem`, no `world.season`, no catch-up. The engine owns the CYCLE and content owns the names, so a source can ship a two-season world; there is no `order` field on a season, because registration order already is an order and a second one could disagree with it. **A migration may not read a live registry**: `v3-to-v4` was written first calling `createInstalledRegistries()`, which is wrong in a way that would have hidden for a long time — the same save would migrate to two different worlds on two machines, and the golden fixture meant to catch that would itself vary by environment. The four shipped seasons are a frozen literal, and the mutation control makes the payoff visible: reordering `coreSeasons()` fails the registry test and leaves the migration test untouched. This link **synthesises where `v1 → v2` refused to**, and the distinction is that a v1 save carried no record of its sources so any manifest would have been a claim nobody made, whereas a v3 save carries no seasons because seasons did not exist yet — the test is whether the value was ever ambiguous, not whether it was ever written. Seasons gate what may be **planted**, never what may be kept: a standing crop always matures (ADR-021 §3), and out-of-season folds into the no-seeds branch phase-06b already built, so a worker is never idled by the calendar. Writing the no-deadlock test surfaced that **the out-of-season worker path is reachable only through the seed bin** — without one a worker only ever sows the year-round turnip — and the first version of that test was wrong because it did not know this. The turnip's empty seasons list is therefore load-bearing rather than a tuning gap. Catch-up refuses the WHOLE gap rather than the legal part of it (ADR-021 §5's "where the model cannot be certain it credits nothing"), guarded by the existing never-over property extended to boundary-spanning gaps plus a paired control, without which the rule would be indistinguishable from "no replants across any boundary". A seasonal price modifier joins ADR-013 §4's pipeline — now a product of modifiers floored exactly ONCE, band [0.90, 1.00], never above 1.00 because the base price is the ceiling a player is allowed to memorize — and it reads the crop that YIELDS an item rather than an id that matches it, so a source shipping `mod:melon` yielding `mod:melon_flesh` is not silently unpriced. **`seasonChanged` was not built**; ADR-021 §6 carries the amendment. Two of ADR-021 §2's three declared surfaces shipped: the seasonal harvest-yield modifier is named in the phase doc as left out, because it is the one that most directly reduces what a player gets for work already done. Also recorded: the season-crossing property test first used the eight-hour cap and **stalled `test:coverage` past ten minutes while passing `npm test` in two** — walking into the trap the note directly above it warns about, that V8 instrumentation costs roughly 3.5×.
- **Phase 10 — time simulation** (ADR-020; schema **v2 → v3**): the world has a day, and nothing depends on it — deliberately. Day, time-of-day and phase are **pure functions of `world.tick`**: no new system, no new mutable state, no catch-up, no accuracy contract, because the tick counter is already the accumulator (the ADR-009 §2 precedent applied to time). What v3 adds to the save is not the calendar but its two **inputs** — `ticksPerDay` and the phase set — frozen at world creation, because changing either reinterprets the whole past: halve the day and a player on day 40 is silently on day 80, with every "planted on day 12" memory now wrong. A day is 24,000 ticks (20 real minutes) through four phases — dawn, day, dusk, night. **The simulation publishes a phase and never a fraction of a day**: a `timeOfDay` field would be correct, one line, free to compute, and would republish its slice on all 24,000 ticks, which ADR-005 §2 names a defect outright. Four phases means four republishes, the same move `CropStage` makes for growth. The guarantee is asserted on **both sides of the sim→view boundary** because neither side can see the other's failure — the sim test steps the real tick loop through a full day and expects the slice version to advance by exactly four; the React test counts Profiler commits over the same day and expects four, delivered in hundredths so the store's throttle cannot coalesce two boundaries into one notification. **Layer 5 is claimed**, reserved empty by ADR-001 since phase-02 and filled with no re-layering migration — the payoff `layers.ts` had already recorded for layer 4. The tint is a plain alpha-filled rectangle rather than a blend mode, so ADR-001 §Fallback's canvas backend gets a dimmer night rather than no night; the phase→tint mapping is **registered content**, supplied by `plugins/core` through the public API with no privileged path. Every transition is **finite**: it runs 900 ms, holds one animation lease, and releases it, so the idle state is zero frames by construction rather than by care. That lighting view **stays in the measured coverage set instead of joining the host-binding exclusions** — Pixi's `Graphics` builds geometry without a renderer, so the test drives it against the **real** `createDirtyGate`, making `animationCount()` the same number the render loop consults; ADR-020's "zero rAF across a phase boundary" acceptance is asserted there rather than in an e2e spec, because a boundary is five real minutes away and no fast-forward hook exists. **`dayPhaseChanged` was never built, and ADR-020 §3 now carries the amendment saying so.** Its only named consumer was the lighting view, and by the time that view existed the `time` slice already delivered the phase through the same republish path every other view uses — decisively, a save resuming mid-day _publishes_ but does not _fire_, so an event-driven view would hold its default tint for hours. The ADR's own producer-and-consumer rule is what ruled the event out; it was applied, not waived. **+66 tests (1,968 → 2,034)**, each milestone with a mutation control: publishing a continuous time value fails five tests including both republish counters, and never releasing the animation lease fails six. One of those controls found a **worthless test of my own** — the offline-exactness check passed while `deserialize` dropped `ticksPerDay` entirely, because it was built on a default-length day and the fallback supplied the very value being asserted; rebuilt on a 9,000-tick day it fails under that mutation. **A persisted constant tested at its default is not tested at all**, which is now recorded for the two remaining ADR-027 links that add one. A mutation control in 10a also exposed a **documentation** defect rather than a code one: a comment claimed `PHASE_STARTS[0]` "MUST be 0" when `phaseFor` walks backwards and never reads index 0 at all.
- **Phase 09 — plugin loader & capability registry** (ADR-019, ADR-026, ADR-027; schema **v1 → v2**): a third party can add content without touching engine source. One sentence from ADR-019 §6 governs almost every decision — _a failure refuses exactly one source, names it, and leaves the rest loaded_ — so every layer is **total**: each directory comes back installed or refused with a reason, and the reason survives all the way to a panel the player can read. **A contested namespace refuses every claimant**, resolving a conflict between `plugins/manifest.schema.json` (reject both) and `ROADMAP.md` §5 (refuse one) in the schema's favour, because it is the contract authors write against and because picking a winner needs a rule for who is first: ordering by id decides whose content survives by alphabet, ordering by install time makes a save load differently tomorrow. Version ranges are **refused rather than guessed** — `*`, an exact version and `^x.y.z` are understood, while `>=1.0.0`, `~1.2.3` and `1.x` are refused by name, because a range the engine misreads surfaces later as content that is simply not there. The `v1 → v2` migration **invents nothing**: `world.sources` migrates to the empty manifest rather than a synthesised `core` entry, because every v1 save WAS written by a build with core content, so the invented entry would look right and would be a lie; and `disabledSources` records what is OFF rather than what is on, so an `enabled: []` default cannot silently disable core on every v1 save ever written. The pre-migration backup's exemption from pruning is **structural** rather than a rule someone must remember — its filename cannot match `pruneBackups`'s filter, and a test pins the two against each other. **Path traversal was a real vulnerability**, found and closed while writing the file-reading code: definition paths come from a downloaded manifest and `readFileSync` will follow `../../../` out of the plugins directory; a declared path must now resolve inside the source, and an absolute path is refused. Only `crops` and `items` are admitted, and an unknown kind is **refused rather than ignored**, so an author who writes `"buildings"` is told instead of watching it vanish. Two defects found by this phase's work were fixed on the way: the catch-up over-credit (`phase-07.7` debt #13) and the unpinned seeds guarding it (#14).
- **Phase 08 — content identity & plugin foundation** (ADR-019, ADR-026; no schema change): closes ADR-003 §6's gap, which had been unbacked since phase-00 — _"the API is proven sufficient by first-party content before any third party depends on it"_ was a claim about a `PluginApi` that did not exist in the repository. `plugins/core/` now registers every core definition through the public API and nothing else: no privileged path, no internal shortcut, no capability reachable from there that a third-party source cannot reach, which is what keeps ADR-026 §2's "the engine never branches on provenance" true at the one seam where it matters most. The four `registerCore*` bodies were moved **by script**, so no value could drift. A namespace is owned by exactly one source permanently, a collision refuses both claimants, and reserved namespaces are refused to third parties. The `sim ↛ plugins` constraint was resolved with an **ambient installed-source registry** — a module-level registry that lets `createWorld` receive content without the simulation importing plugins. `tests/provenance-blindness.test.ts` greps comment-stripped code so `src/sim` cannot read provenance at all, and `src/persistence` cannot BRANCH on it, which is the honest rule: ADR-026 §4 requires the save to record provenance, so a blanket ban there would have been unimplementable. Byte-identical saves were **proven by measurement** rather than asserted — sha256 `f8e920f5…c380`, 34,158 bytes, before and after the migration. One find worth keeping: `core:wheat` is both a crop id and an item id, so the API's duplicate check keys on `kind:id` — uniqueness is per registry, never across a bundle.
- **Phase 08.0 — coverage reconciliation** (tests and policy; no gameplay change): the v0.1 release gate turns green, from **67.29% lines / 66.48% branches against 80 / 75** to **95.26% / 85.95% against a raised 90 / 85**, with every per-area threshold higher than the one it replaced and none lowered. The gate had been red since 07e and each close called the cause "structural" without naming it; it was three things at once. **Six of the seven thresholds `TESTING.md` §4 published had never been enforced** — `vitest.config.ts` carried a single global pair from phase-00 onward, so the rest were prose, and three areas had been below their documented bars for months including `src/persistence`, the highest bar in the project and the code that protects saves. **The measured set was wrong**: 1,378 lines of Pixi and Electron binding sat in the denominator contributing 34 covered lines, which dragged `src/renderer/render` to 34% while the logic extracted out of it sat at 98.94% — that is what made the published numbers look unreachable and made lowering them look reasonable. **And real gaps hid behind the arithmetic.** `TESTING.md` §4.2 now states the criterion for leaving the measured set — a file must be a **host binding** AND name a test that does exercise it — which is the repository's own rule rather than a new one, since `save-store.ts` states it as doctrine ("the directory is a parameter, not `app.getPath`"); applying it moved nine thresholds up and none down, because 9 of the 23 excluded files already had a covered `logic` counterpart from which they were extracted phases ago. - **v0.2 Phase 0 — architecture refresh & roadmap** (docs only, no runtime change): the design phase that turns a finished application into an extensible engine. All eighteen existing ADRs reviewed against ten architectural goals; **none required replacement** — six get successor ADRs, one (ADR-009) constrains without changing, and eleven stand unamended. Nine new ADRs. **ADR-026 (content identity)** is the foundation and was not in the original brief: designing save compatibility around _plugins_ specifically would make official packs, generated packs, and DLC either special cases or lies, so one identity model covers all five kinds — a namespace is owned by exactly one source, a source declares a provenance the engine **records and never branches on**, and one isolation invariant replaces two adjacent rules: _removing a content source may affect only entities, containers, side-tables, and partitions in namespaces that source owns; nothing else in the save may change._ **ADR-019 (plugin architecture)** makes the API an explicitly versioned public contract — compatibility declared against `PLUGIN_API_VERSION`, never the engine version, because engine releases move for reasons no plugin can observe. The full capability surface is specified; **v1 declares the subset that executes no plugin code**, since `script-src 'self'` has no `unsafe-eval` and ADR-001 recorded that the CSP stayed strict _specifically because_ plugins run in the renderer — so determinism and save safety are structural rather than promised. Commands, listeners, panels, and services are API v2, with the four questions a successor ADR must answer named rather than stubbed. **ADR-020/021/022** discovered that the day, the season, the weather, and tile wetness are all **derivations, not systems** — v0.2 adds nothing to `TICK_SYSTEMS`, and ADR-022 §2 makes that the detector: if weather needs a tick slot, the design is wrong. Because weather is a pure function of `(seed, period, season)`, rainfall over any span decomposes into whole periods — **a piecewise-constant rate history that never had to be stored**, which is the second mechanism ADR-009 §2 named, obtained for free, so weather-modulated growth becomes possible with no accumulator and no error budget. **ADR-024** replaces "worker priorities" with a three-stage scheduling pipeline, because a reorderable list answers one of six roadmap concepts and turns the other five into special cases — including emergency override, which would have arrived as the privileged write path ADR-010 §6 exists to forbid. **ADR-023** answers the ambient-audio question ADR-016 §4 deferred, with five conditions and a measured budget as the gate. **ADR-025** found that **rollback across a schema bump orphans a save** — every component behaving correctly, composing into data loss — and bounds rollback by schema version. **ADR-027** answers ADR-015's Open Question 1: pre-migration backups kept indefinitely, because ADR-025 makes them the only recovery path rather than insurance.

- ADR-018, developer tooling and debug architecture (decided ahead of phase-07.8): formalises the rules phase-01.5 followed by convention and never wrote down, at the moment phase-07.8 will roughly quadruple the tooling surface and add the first tools that **write** to the world. Ten decisions, of which three matter most because they erode silently. **Debug tools never mutate simulation state directly** — spawn, remove and reset submit commands through the ordinary player source and are validated and rejectable like any other (ADR-010 §6), which buys replayability, rejectability, and the property that a bug reproduced with debug tools is a real reproduction; the console's existing `money` command is the model. **Tooling consumes events and never produces them**, because a debug-produced event would make the event graph differ between builds and a bug depending on event ordering would stop reproducing in the only build equipped to diagnose it. **Debug rendering obeys render-on-demand** — a closed overlay costs nothing and an open one takes an animation lease like anything else that moves (ADR-017 §1), with live graphs called out as the trap: a 60-second history repainting at 60 Hz makes the thing it measures worse and its own readings untrustworthy. `FEATURE_DEBUG` is confirmed as the single compile-time gate, sub-flags may refine a debug build but none may re-enable tooling in a release, and removal stays asserted against a real built artifact rather than against the source. Five alternatives are recorded as rejected, including the one actually in play — _skip the ADR and keep following phase-01.5's conventions_ — rejected because those conventions exist only as comments in files a new tool need not touch. Filed in `docs/decisions/` rather than the requested `docs/adr/`: every ADR from 001 lives there and ADR-012 freezes that set by path, so a second directory would split the record. No code, no save-format impact, no simulation impact; existing tooling already complies.

- Performance validation and instrumentation (phase-07.7M — **the three open budgets, measured**): the tick budget in `PERFORMANCE.md` is stated as a **p99** and nothing in this project could measure one — the loop reported a rolling ticks-per-second, which is an average and hides exactly the tail a p99 exists to expose, so "p99 tick unchanged" had never been a checkable claim. A duration histogram now keeps a ring of the last 4,096 samples (rather than bucketed counts, which answer with a bucket edge when the question is whether a budget was met), records allocation-free into a pre-allocated array, and is **absent from production by construction** — `FEATURE_PROFILER` is a compile-time literal, so a release build takes the loop's un-instrumented branch and Rollup drops the module. A repeatable harness (`tests/e2e/perf-harness.spec.ts`) measures against a real window and writes every result to `docs/perf/*.json`, so a number quoted in a document has a file behind it rather than a memory of a run. **Criterion 5: 0.100 ms p99 against a 3 ms budget** over 1,287 batches — recorded honestly, since `performance.now()` is coarsened to 0.1 ms here, so the 0.000 ms p50 means _below the clock's resolution_ rather than _instant_. **Criterion 8: 100 FPS with one animation lease while the pointer is active, 0 FPS with 0 leases after 14 s untouched** — ADR-017 §2 condition 4 proven end to end rather than argued, and the measurement that makes the ambient-motion exception legitimate instead of a hole in ADR-001; it could not be taken until 07.7L made the setting reachable. **Criterion 11: 3.2 MB heap growth over 30 minutes at 99.7% active, against a 25 MB ceiling** — and the shape matters more than the number: flat for twenty minutes, one step, flat for ten, which is a one-time allocation rather than the progressive growth a leak produces, so the linear extrapolation to ~51 MB over eight hours would be wrong. **The first 30-minute soak was invalid and is kept as evidence**: it moved the pointer once per five-second sample, the IPC metric reads pushed the gap past the 8 s presence timeout, and **66% of it ran idle** — measuring the cheap state the test exists to avoid while reporting a confident 0.00 MB. Nothing in the output looked wrong; it was caught by checking the animation column rather than trusting the number. The harness now reports `activeShare` and asserts it exceeds 0.8. Two limitations are documented rather than smoothed over: `performance.memory` is quantised (two distinct values across 298 samples), so growth is bounded below its bucket size but not shown byte-stable — CDP `Runtime.getHeapUsage` is the recorded improvement — and these figures come from a 28-core desktop, making them a ceiling check rather than a floor. **No optimisation was performed**, because nothing exceeded a budget. One E2E flake was attributed rather than assumed: `save.spec.ts`'s autosave-cadence test fails identically at the pre-phase commit (61 ticks) as it does with the instrumentation on (272) and off (24), and passed once the machine settled — it is load-sensitive, not a regression.
- Game feel (phase-07.7, ADR-017 — **the farm responds to being touched**): tilling throws dust, a seed presses in, a growth stage swells and sparkles, a harvest lifts and fades while leaves scatter and a `+n` rises, a sale bursts gold at the market stall, and workers ease into their steps and finally **swing while they work**. That last one was a defect rather than an addition — a six-frame `harvest` animation shipped with the phase-05.5 character set and `selectAnimation` mapped `Working` straight through to `idle`, so a worker tilling, planting, or harvesting stood perfectly still for the whole task. It is the third instance this project has found of art sitting in the atlas with no code path to it, after the tilled-soil sprite and the crop stages. **The brief contradicted itself, and ADR-017 resolves it**: §12 forbids violating render-on-demand while §3 and §10 ask for a rotating windmill, drifting clouds, and swaying grass — all unbounded, all of which would hold the frame loop open forever on a window that sits on the player's screen for eight hours. Motion is now one of two classes. Finite effects acquire an animation lease, run, and release, so they cost nothing at idle and default ON. Ambient motion defaults OFF, never runs collapsed or in work mode, and **surrenders the frame loop when the pointer has been idle for eight seconds** — which restates ADR-001's invariant rather than repealing it: when the world is static _and_ the player is absent, no frame is drawn. `bindAnimationLease` makes the lease structural instead of a habit, since `dirty-gate` calls its animation count "the fragile half", two call sites carried that bookkeeping by hand, and this phase would otherwise have added five more. Everything visual is **pooled with a fixed ceiling and allocates nothing after construction**: the particle pool's test collects the view objects handed out at capacity, runs three thousand emissions, and asserts no object outside that set is ever returned. All presentation randomness is a **hash, not a generator** — its guarding test interleaves unrelated calls between related ones and asserts the results do not move, which a generator cannot pass, because a decorative particle drawing from `world.rng` would advance the stream a saved game resumes from and desynchronise every future tick. Floating numbers compose eleven glyph textures into pooled per-digit sprites rather than using Pixi's `Text`, which rasterises a texture per distinct string. Camera shake ships **off** and is asserted to return to exactly zero, since a shake ending a fraction of a pixel off displaces the camera permanently and a hundred of them accumulate. HUD feel is CSS transitions on compositor properties, so React never re-renders for it — and the game's own Reduced Motion switch now reaches CSS at all, which it previously did not. **Fourteen named effects were refused with stated reasons** rather than faked: scratch-head and sit need pose art that does not exist; worker-step is an ambient bed with extra steps; button-hover fires while the player is reaching for another window; grass sway would mean re-rendering baked terrain chunks every frame; and no windmill, chimney, or flag exists to animate. **Not complete:** the six accessibility settings gate every effect correctly but have **no user interface** — they are reachable only by hand-editing `settings.json` — and the p99 tick and 30-minute heap budgets are unmeasured.
- Autosave, the return summary, and the phase-07 close (phase-07e — **the game now saves itself**): every trigger `SAVE_FORMAT.md` §7.2 names is live — the 60-second cadence, quit (which **blocks shutdown**, capped at 3 s so a wedged renderer can delay it but never prevent it), close-to-tray (quick hide, this overlay's only true absence), major transactions, and a manual button in settings. Triggers live in the main process and the document lives in the renderer, so every one of them becomes the same `save:requested` event and there is still exactly one serialization site. The cadence derives its period from `AUTOSAVE_INTERVAL_TICKS` rather than restating "60 s", so the wall-clock timer main needs cannot drift from the tick constant. **Coalescing lives only in the renderer**, the one side that can see a write in flight: one write at a time, and a burst during it collapses to a single follow-up — collapsed, not dropped, because the trigger that lands mid-write is often the quit save. Serialization is deferred out of the frame that asked for it, since the transaction trigger fires from a snapshot subscriber inside `store.pump`. Major transactions are read from the **snapshot** rather than the command stream: a command can be submitted and rejected, but a slice only changes when the world did. The §9.4 **return summary** reports time away, harvests, coins earned, and what blocked progress ("Storage full after 2h 14m"), dismissible and never modal — and **defers in work mode rather than vanishing** (ADR-014's stated requirement, the reason work mode had to ship before phase-07): the controller holds the report while the HUD is hidden, so leaving work mode shows what the player never got to read. A **save failure** carries the path — only main knows it, and the renderer never derives one — persists instead of auto-dismissing, clears itself when a later save succeeds, and shows in work mode too, because withholding "your game is not being saved" to keep the desktop quiet is misleading rather than quiet. Write failures are proven with real filesystem refusals, each asserting the good save on disk is untouched; disk-full is deliberately unmocked (same call, same `catch` — mocking it would test Node's error plumbing). Measured on the reference farm: **38,730-byte** save against a 2 MB ceiling, **0.64 ms** serialization against 100 ms, **1.35 ms** load + catch-up at the full 8-hour cap against 1.5 s, and memory growth over an accelerated 8-hour run under the 25 MB ceiling. E2E now proves the app saves with nobody asking — quitting, the real 60-second cadence with no test seam shortening it, a worker hire, and SIGKILL mid-write followed by a clean relaunch into the same farm.

- Ground decoration (phase-07.5e — **the world outside the farm is a place now**): trees, rocks, bushes, and flowers scatter the unowned land, from art that already shipped — no new assets. Three rules keep a cosmetic system from becoming a gameplay one, each of them a test: it **touches nothing** (not a building, not an entity, not in the save; a worker walks straight through a bush because the bush does not exist to the simulation); it is **derived, never rolled** — placement is a pure hash of seed and tile, deliberately not `world.rng`, since drawing from the simulation's generator would advance the stream a saved game resumes from and desynchronise every future tick, with a test asserting the generator is byte-identical across a full plan; and it **stays off the farm**, with a tile that becomes the player's losing its tree on the next plan, which is how land expansion reclaims scenery. - UI accessibility (phase-07.5d — **contrast is now measured, and keyboard focus is visible**): WCAG 2.2 contrast maths implemented directly and asserted over every colour pair the HUD uses, measured against a **white backdrop** because a translucent overlay sits on whatever wallpaper the player has — passing there means passing anywhere. - Camera focus (phase-07.5c — **the camera helps, and never fights**): an eased glide brings a selected worker or a newly placed building into view, and **declines to move at all when the target is already comfortably on screen** — moving to show something the player is already looking at is disruption, not help. Any pan or zoom abandons a glide instantly, mid-flight, with no easing out and no resumption. The glide lands exactly on its target and holds an animation lease only while running, so render-on-demand is untouched. Two of the directive's four focus triggers were declined on purpose: loading a save already frames the owned plot geometrically at construction, and focusing on every completed harvest would make a companion unusable — harvests fire several times a minute on a mature farm, and the burst already marks the spot. Zoom limits and edge clamping were examined and left alone: clamping already pins correctly when the world is narrower than the viewport, and zoom is already integer-only with the viewport centre preserved, because non-integer zoom resamples pixel art.

- Audio (phase-07.5a, ADR-016 — **the loop now answers you**): eight placeholder sounds, scripted and deterministic, wired to things that already happened rather than to intents — harvest and sale ride published events; deposit and placement ride settled snapshots; a rejected purchase and an illegal placement stay silent. - Save-compatibility gate for v0.1 (`fix/0.1/7.2.md` — verification only, no gameplay): `docs/save-compatibility-report.md` states what the format promises every save file a player will own, and `tests/save-compatibility.test.ts` (45 tests) is the evidence for each claim — exercising the **whole** pipeline (serialize → bytes → parse → migrate → validate → repair → hydrate) rather than any one stage. **`save → load → save` is byte-identical**, not merely equivalent, across seven scenarios (empty, minimum, 1,600-tile large world, 30 workers, full inventory, full storage with a 2-billion-coin wallet, 20,000 simulated ticks) and over **100 consecutive cycles**. ### Fixed

- **Catch-up over-credited a shift-constrained crew** (ADR-024 §4, found by phase 14’s verification pass). `anyWorkerMayWork` asked `phaseFor(world.tick)` — **one** day phase — and applied the answer to a catch-up window of up to eight hours, so a crew on shift for one phase in four was credited exactly what an unconstrained crew earned. It survived four tests because every one of them constrained by **zone or task kind**, and neither changes with the clock: evaluating those once is correct, so the tests were right about what they covered and silent about what they did not. The correct shape was already in the same function — `plantableThroughout` asks `seasonsBetween` for every season a window touches — so `phasesBetween` is now its counterpart, named to match, and permission is required **throughout** the window. "Throughout" is asked per worker rather than per phase: crediting a cycle needs one worker who could have done it for the whole window, not a relay who each could have done part, because the model never decided which worker did a cycle. The fix is conservative — a partially-on-shift crew is credited nothing rather than a share — which is acceptable today because **no shipped role declares a shift**; the field exists and core’s three roles constrain task kinds only, so this bounds a future shift correctly and changes nothing a player can reach. A proportional share is the better answer once a role declares one, and is a change to make with that role in hand.

## Versioning Rules

### Two version numbers

This project tracks **two independent versions**. Confusing them causes save-compatibility bugs.

| Version                 | Format                  | Meaning                     | Where                                   |
| ----------------------- | ----------------------- | --------------------------- | --------------------------------------- |
| **App version**         | Semantic (`0.1.0`)      | The release the player sees | `package.json`, `meta.gameVersion`      |
| **Save schema version** | Integer (`1`, `2`, `3`) | The persisted data format   | `schemaVersion` (`SAVE_FORMAT.md` §4.1) |

They move independently. A patch release may bump the schema; a minor release may not. **Only `schemaVersion` controls migration** — `meta.gameVersion` is informational and must never drive logic (`SAVE_FORMAT.md` §2.1).

### Semantic versioning, as applied here

Pre-1.0, the conventional rules are adapted to the roadmap in `PLAN.md`:

| Bump                | Means                                               | Example         |
| ------------------- | --------------------------------------------------- | --------------- |
| **MAJOR** (`1.0.0`) | v1.0 — the feature-complete life simulator          | Reserved        |
| **MINOR** (`0.2.0`) | A roadmap tier: new systems, possibly a schema bump | v0.1 → v0.2     |
| **PATCH** (`0.1.1`) | Fixes, balance, performance; no new systems         | Bug fix release |

**Backward compatibility is never broken**, at any bump (`AI_RULES.md` §1.4). A v0.1 save must load in v1.0. There is no version increment that licenses breaking a save.

## Entry Format

### Categories

Use these six, in this order. Omit empty ones.

| Category     | For                          |
| ------------ | ---------------------------- |
| `Added`      | New features                 |
| `Changed`    | Changes to existing behavior |
| `Deprecated` | Features to be removed later |
| `Removed`    | Features removed now         |
| `Fixed`      | Bug fixes                    |
| `Security`   | Vulnerability fixes          |

### Writing entries

Entries are for **players**, not developers. The reader wants to know what changed about the game, not which module was refactored.

```markdown
## [0.2.0] - 2026-XX-XX

### Added

- Weather system: rain automatically waters crops
- Plugin loader — mods can now add crops, items, and buildings
- Day/night cycle affecting worker schedules

### Changed

- Wheat growth time reduced from 120s to 100s
- Market Stall now sells at 92% (was 90%)

### Fixed

- Workers no longer stall when storage fills while carrying items
- Overlay re-docks correctly after a DPI change

### Save Compatibility

- Schema version 1 → 2 (adds weather state)
- v0.1 saves load automatically; no player action needed
```

### The Save Compatibility section

**Required on any release that bumps `schemaVersion`.** It must state the version transition and, in plain language, what the player needs to do — normally "nothing."

This section exists because save compatibility is the promise this project makes most seriously, and a release that changes the format without saying so undermines it even when the migration works.

### Rules

- **Player-facing language.** "Workers no longer stall when storage fills," not "fixed null deref in `deposit-task.ts`."
- **No internal refactors.** If it does not change what the player experiences, it does not belong here (that is what git history is for).
- **One line per change.** Link to an issue if there is detail worth having.
- **Add to `[Unreleased]` in the same commit as the change** (`AI_RULES.md` §5.4).
- **Balance changes are always listed.** A player who notices wheat is faster deserves to find it here.
- **Performance improvements are listed when measurable**, with the measurement: "Idle CPU reduced from 1.4% to 0.6%."

## Release Process

1. Verify every gate in `PLAN.md` §8 — **including zero known data-loss defects**
2. Move `[Unreleased]` entries under a new version heading with the release date
3. Add the Save Compatibility section if `schemaVersion` changed
4. Bump `version` in `package.json`
5. Confirm every golden fixture still loads (`SAVE_FORMAT.md` §4.4)
6. Tag the release `v<version>`
7. Create a fresh empty `[Unreleased]` section

Step 5 is not optional and not covered by step 1's general test run. It is the specific check that a released build can still load saves from every prior version.
