## [Unreleased]

### Added

- **v0.2 Phase 0 — architecture refresh & roadmap** (docs only, no runtime change): the design phase that turns a finished application into an extensible engine. All eighteen existing ADRs reviewed against ten architectural goals; **none required replacement** — six get successor ADRs, one (ADR-009) constrains without changing, and eleven stand unamended. Nine new ADRs. **ADR-026 (content identity)** is the foundation and was not in the original brief: designing save compatibility around _plugins_ specifically would make official packs, generated packs, and DLC either special cases or lies, so one identity model covers all five kinds — a namespace is owned by exactly one source, a source declares a provenance the engine **records and never branches on**, and one isolation invariant replaces two adjacent rules: _removing a content source may affect only entities, containers, side-tables, and partitions in namespaces that source owns; nothing else in the save may change._ **ADR-019 (plugin architecture)** makes the API an explicitly versioned public contract — compatibility declared against `PLUGIN_API_VERSION`, never the engine version, because engine releases move for reasons no plugin can observe. The full capability surface is specified; **v1 declares the subset that executes no plugin code**, since `script-src 'self'` has no `unsafe-eval` and ADR-001 recorded that the CSP stayed strict _specifically because_ plugins run in the renderer — so determinism and save safety are structural rather than promised. Commands, listeners, panels, and services are API v2, with the four questions a successor ADR must answer named rather than stubbed. **ADR-020/021/022** discovered that the day, the season, the weather, and tile wetness are all **derivations, not systems** — v0.2 adds nothing to `TICK_SYSTEMS`, and ADR-022 §2 makes that the detector: if weather needs a tick slot, the design is wrong. Because weather is a pure function of `(seed, period, season)`, rainfall over any span decomposes into whole periods — **a piecewise-constant rate history that never had to be stored**, which is the second mechanism ADR-009 §2 named, obtained for free, so weather-modulated growth becomes possible with no accumulator and no error budget. **ADR-024** replaces "worker priorities" with a three-stage scheduling pipeline, because a reorderable list answers one of six roadmap concepts and turns the other five into special cases — including emergency override, which would have arrived as the privileged write path ADR-010 §6 exists to forbid. **ADR-023** answers the ambient-audio question ADR-016 §4 deferred, with five conditions and a measured budget as the gate. **ADR-025** found that **rollback across a schema bump orphans a save** — every component behaving correctly, composing into data loss — and bounds rollback by schema version. **ADR-027** answers ADR-015's Open Question 1: pre-migration backups kept indefinitely, because ADR-025 makes them the only recovery path rather than insurance.
- **Four defects found in the shipped v0.1 record during the review**, each recorded rather than quietly fixed. **`plugins/core/` was never built** — ADR-003 §6's load-bearing claim that _"the API is proven sufficient by first-party content before any third party depends on it"_ has not held, because core content registers through `registerCoreCrops(...)` called from `src/sim/world/world.ts` and there is no `PluginApi` object in the repository. Most of the hard part did ship (namespaced permanent IDs, generic typed registries, the event bus, the dispatcher, save partitioning with quarantine, and a correctly-configured lint boundary zone), so Phase 08 is a migration with four exact bounds and **unmodified existing tests as its acceptance proof**, not a rewrite. **`tiles.moisture` is stored, serialized, validated, and read by nothing** — dead accumulator-shaped state in the save format, written for a moisture model ADR-009 deferred and never built; ADR-022 replaces it with `wateredAt`, so v0.2's first removal migration takes a field _out_ of the format. **`ARCHITECTURE.md` §3.2–3.3 documented a `growthSystem` and a `harvestSystem` that do not exist** — the phase-0 sketch, never corrected after ADR-009 made growth a derivation. **`plugins/manifest.schema.json` required `gameVersion`** — compatibility against the engine version, the coupling ADR-019 §1 forbids — and required an `entry` module, which presumes code; both amended in this phase, since the schema is a published contract rather than source.
- **Documentation:** `ROADMAP.md` (new) owns v0.2 phase execution — ten phases, each with purpose, dependencies, deliverables, risks, acceptance criteria, documentation changes, testing strategy, and commit boundary, every one independently testable; `PLUGIN_API.md` and `PLUGIN_GUIDE.md` (new, outlines with their ownership and fixed rules decided); `PLAN.md` §3 rewritten to the real phase table and ceding phase detail to `ROADMAP.md`; `VISION.md` gains §4.3, the v0.2 paid-forward table, authorising the engine widening under §4.2's discipline; `ARCHITECTURE.md` gains §14 (the content-source system) and §8.1 (the `plugins/core/` gap, recorded as evidence for ADR-003 §6's own prediction that a reserved-but-unused seam does not stay honest); `SAVE_FORMAT.md` gains §8.1–8.2 and §11 (the five-link v0.2 chain, the removal pattern, backup retention); `ASSETS.md` gains §10.1, _assets carry no gameplay logic_; `plugins/README.md` rewritten from a mod document into a content-source document. **The requested `ASSET_PIPELINE.md` was deliberately not created** — `ASSETS.md` and `docs/assets/AI_ASSET_PIPELINE.md` already own that ground and a third file would violate `AI_RULES.md` §5.3.
- **Phase 07.8 — the developer toolkit**, fifteen milestones under ADR-018. A completed F3 overlay; a hardened metrics API; world and entity inspectors with pinning; event and command monitors, both bounded and both subscribe-only; time controls with 1–16× scaling; a performance panel graphing sixty seconds of FPS, frame time and heap; chunk and pathfinding overlays that draw into the scene; spawn tools that dispatch commands; a screenshot mode; session recording with JSON export; and shared panel chrome giving every panel drag, resize, search and a remembered layout. Roughly 40% of the brief already existed and was extended rather than replaced. **The tooling is compiled out of production**, asserted by 31 markers against a real build artifact, and **the release bundle grew by 41 bytes** — one forwarded option and a folded spread, no tooling, recorded exactly rather than rounded away. Three parts of the brief were deliberately **not** built, each because building them honestly was impossible: per-command execution timing and A\*'s open/closed sets would both have required changing `src/sim` for a debug tool, and a `speed` console command would have been untested surface. Along the way the tooling's own tests found four real defects — a click on a filter chip tilling the tile behind it, a developer console that could not be clicked into at all with a real mouse, a flat performance graph drawn along the floor where it read as a stall, and panels whose resize grips fell off the bottom of a 220-pixel-tall overlay.
- ADR-018, developer tooling and debug architecture (decided ahead of phase-07.8): formalises the rules phase-01.5 followed by convention and never wrote down, at the moment phase-07.8 will roughly quadruple the tooling surface and add the first tools that **write** to the world. Ten decisions, of which three matter most because they erode silently. **Debug tools never mutate simulation state directly** — spawn, remove and reset submit commands through the ordinary player source and are validated and rejectable like any other (ADR-010 §6), which buys replayability, rejectability, and the property that a bug reproduced with debug tools is a real reproduction; the console's existing `money` command is the model. **Tooling consumes events and never produces them**, because a debug-produced event would make the event graph differ between builds and a bug depending on event ordering would stop reproducing in the only build equipped to diagnose it. **Debug rendering obeys render-on-demand** — a closed overlay costs nothing and an open one takes an animation lease like anything else that moves (ADR-017 §1), with live graphs called out as the trap: a 60-second history repainting at 60 Hz makes the thing it measures worse and its own readings untrustworthy. `FEATURE_DEBUG` is confirmed as the single compile-time gate, sub-flags may refine a debug build but none may re-enable tooling in a release, and removal stays asserted against a real built artifact rather than against the source. Five alternatives are recorded as rejected, including the one actually in play — _skip the ADR and keep following phase-01.5's conventions_ — rejected because those conventions exist only as comments in files a new tool need not touch. Filed in `docs/decisions/` rather than the requested `docs/adr/`: every ADR from 001 lives there and ADR-012 freezes that set by path, so a second directory would split the record. No code, no save-format impact, no simulation impact; existing tooling already complies.
- **Phase 07.7 closed** (phase-07.7N): eight documents synchronised, every acceptance criterion audited to a verdict, and the technical debt registered rather than fixed. **16 of 16 criteria PASS, 0 BLOCKED**, with the three performance criteria backed by evidence files in `docs/perf/`. Twelve items are recorded in the debt register with reason, impact, and recommended action — the coverage gate (63.41% against 80%, moved the wrong way for the same structural reason as 07e and 07.5f), the quantised heap instrument, single-machine performance figures, two known flakes, and the eight named effects refused for want of art or for architectural cost. The audit found no TODO, no FIXME, no unreachable setting, and no dead UI. `ARCHITECTURE.md` gains §12, the motion layer; `PERFORMANCE.md` §4.2's invariant table was corrected (it named a test file that has never existed) and §11 records the measurements and their limits; `GAME_DESIGN.md`, `VISUAL_REFERENCE.md`, `TECHNICAL_ASSET_SPEC.md`, `PLAN.md`, and `PROJECT_STRUCTURE.md` describe what shipped. The phase's lesson, recorded because it recurred four times in one phase: **the defect in this codebase is rarely broken code — it is finished code with no path to it.**
- Performance validation and instrumentation (phase-07.7M — **the three open budgets, measured**): the tick budget in `PERFORMANCE.md` is stated as a **p99** and nothing in this project could measure one — the loop reported a rolling ticks-per-second, which is an average and hides exactly the tail a p99 exists to expose, so "p99 tick unchanged" had never been a checkable claim. A duration histogram now keeps a ring of the last 4,096 samples (rather than bucketed counts, which answer with a bucket edge when the question is whether a budget was met), records allocation-free into a pre-allocated array, and is **absent from production by construction** — `FEATURE_PROFILER` is a compile-time literal, so a release build takes the loop's un-instrumented branch and Rollup drops the module. A repeatable harness (`tests/e2e/perf-harness.spec.ts`) measures against a real window and writes every result to `docs/perf/*.json`, so a number quoted in a document has a file behind it rather than a memory of a run. **Criterion 5: 0.100 ms p99 against a 3 ms budget** over 1,287 batches — recorded honestly, since `performance.now()` is coarsened to 0.1 ms here, so the 0.000 ms p50 means _below the clock's resolution_ rather than _instant_. **Criterion 8: 100 FPS with one animation lease while the pointer is active, 0 FPS with 0 leases after 14 s untouched** — ADR-017 §2 condition 4 proven end to end rather than argued, and the measurement that makes the ambient-motion exception legitimate instead of a hole in ADR-001; it could not be taken until 07.7L made the setting reachable. **Criterion 11: 3.2 MB heap growth over 30 minutes at 99.7% active, against a 25 MB ceiling** — and the shape matters more than the number: flat for twenty minutes, one step, flat for ten, which is a one-time allocation rather than the progressive growth a leak produces, so the linear extrapolation to ~51 MB over eight hours would be wrong. **The first 30-minute soak was invalid and is kept as evidence**: it moved the pointer once per five-second sample, the IPC metric reads pushed the gap past the 8 s presence timeout, and **66% of it ran idle** — measuring the cheap state the test exists to avoid while reporting a confident 0.00 MB. Nothing in the output looked wrong; it was caught by checking the animation column rather than trusting the number. The harness now reports `activeShare` and asserts it exceeds 0.8. Two limitations are documented rather than smoothed over: `performance.memory` is quantised (two distinct values across 298 samples), so growth is bounded below its bucket size but not shown byte-stable — CDP `Runtime.getHeapUsage` is the recorded improvement — and these figures come from a 28-core desktop, making them a ceiling check rather than a floor. **No optimisation was performed**, because nothing exceeded a budget. One E2E flake was attributed rather than assumed: `save.spec.ts`'s autosave-cadence test fails identically at the pre-phase commit (61 ticks) as it does with the instrumentation on (272) and off (24), and passed once the machine settled — it is load-sensitive, not a regression.
- Game feel (phase-07.7, ADR-017 — **the farm responds to being touched**): tilling throws dust, a seed presses in, a growth stage swells and sparkles, a harvest lifts and fades while leaves scatter and a `+n` rises, a sale bursts gold at the market stall, and workers ease into their steps and finally **swing while they work**. That last one was a defect rather than an addition — a six-frame `harvest` animation shipped with the phase-05.5 character set and `selectAnimation` mapped `Working` straight through to `idle`, so a worker tilling, planting, or harvesting stood perfectly still for the whole task. It is the third instance this project has found of art sitting in the atlas with no code path to it, after the tilled-soil sprite and the crop stages. **The brief contradicted itself, and ADR-017 resolves it**: §12 forbids violating render-on-demand while §3 and §10 ask for a rotating windmill, drifting clouds, and swaying grass — all unbounded, all of which would hold the frame loop open forever on a window that sits on the player's screen for eight hours. Motion is now one of two classes. Finite effects acquire an animation lease, run, and release, so they cost nothing at idle and default ON. Ambient motion defaults OFF, never runs collapsed or in work mode, and **surrenders the frame loop when the pointer has been idle for eight seconds** — which restates ADR-001's invariant rather than repealing it: when the world is static _and_ the player is absent, no frame is drawn. `bindAnimationLease` makes the lease structural instead of a habit, since `dirty-gate` calls its animation count "the fragile half", two call sites carried that bookkeeping by hand, and this phase would otherwise have added five more. Everything visual is **pooled with a fixed ceiling and allocates nothing after construction**: the particle pool's test collects the view objects handed out at capacity, runs three thousand emissions, and asserts no object outside that set is ever returned. All presentation randomness is a **hash, not a generator** — its guarding test interleaves unrelated calls between related ones and asserts the results do not move, which a generator cannot pass, because a decorative particle drawing from `world.rng` would advance the stream a saved game resumes from and desynchronise every future tick. Floating numbers compose eleven glyph textures into pooled per-digit sprites rather than using Pixi's `Text`, which rasterises a texture per distinct string. Camera shake ships **off** and is asserted to return to exactly zero, since a shake ending a fraction of a pixel off displaces the camera permanently and a hundred of them accumulate. HUD feel is CSS transitions on compositor properties, so React never re-renders for it — and the game's own Reduced Motion switch now reaches CSS at all, which it previously did not. **Fourteen named effects were refused with stated reasons** rather than faked: scratch-head and sit need pose art that does not exist; worker-step is an ambient bed with extra steps; button-hover fires while the player is reaching for another window; grass sway would mean re-rendering baked terrain chunks every frame; and no windmill, chimney, or flag exists to animate. **Not complete:** the six accessibility settings gate every effect correctly but have **no user interface** — they are reachable only by hand-editing `settings.json` — and the p99 tick and 30-minute heap budgets are unmeasured.
- Autosave, the return summary, and the phase-07 close (phase-07e — **the game now saves itself**): every trigger `SAVE_FORMAT.md` §7.2 names is live — the 60-second cadence, quit (which **blocks shutdown**, capped at 3 s so a wedged renderer can delay it but never prevent it), close-to-tray (quick hide, this overlay's only true absence), major transactions, and a manual button in settings. Triggers live in the main process and the document lives in the renderer, so every one of them becomes the same `save:requested` event and there is still exactly one serialization site. The cadence derives its period from `AUTOSAVE_INTERVAL_TICKS` rather than restating "60 s", so the wall-clock timer main needs cannot drift from the tick constant. **Coalescing lives only in the renderer**, the one side that can see a write in flight: one write at a time, and a burst during it collapses to a single follow-up — collapsed, not dropped, because the trigger that lands mid-write is often the quit save. Serialization is deferred out of the frame that asked for it, since the transaction trigger fires from a snapshot subscriber inside `store.pump`. Major transactions are read from the **snapshot** rather than the command stream: a command can be submitted and rejected, but a slice only changes when the world did. The §9.4 **return summary** reports time away, harvests, coins earned, and what blocked progress ("Storage full after 2h 14m"), dismissible and never modal — and **defers in work mode rather than vanishing** (ADR-014's stated requirement, the reason work mode had to ship before phase-07): the controller holds the report while the HUD is hidden, so leaving work mode shows what the player never got to read. A **save failure** carries the path — only main knows it, and the renderer never derives one — persists instead of auto-dismissing, clears itself when a later save succeeds, and shows in work mode too, because withholding "your game is not being saved" to keep the desktop quiet is misleading rather than quiet. Write failures are proven with real filesystem refusals, each asserting the good save on disk is untouched; disk-full is deliberately unmocked (same call, same `catch` — mocking it would test Node's error plumbing). Measured on the reference farm: **38,730-byte** save against a 2 MB ceiling, **0.64 ms** serialization against 100 ms, **1.35 ms** load + catch-up at the full 8-hour cap against 1.5 s, and memory growth over an accelerated 8-hour run under the 25 MB ceiling. E2E now proves the app saves with nobody asking — quitting, the real 60-second cadence with no test seam shortening it, a worker hire, and SIGKILL mid-write followed by a clean relaunch into the same farm.
- The v0.1 Release Candidate report (phase-07.5f): measurements, before/after, known limitations, and the honest release position in `docs/phases/phase-07.5-vertical-slice.md`. Every save-system budget still holds after the polish phase, the renderer bundle grew 1.6% across all of 07.5, and the placeholder audio set totals 129 KB. **v0.1 is feature-complete and does not yet pass its own release gates:** seven of eight `PLAN.md` §8 gates are green, and coverage — the eighth — moved the wrong way, from 67.36% to **65.55% lines / 64.10% branches** against the required 80% / 75%. The reason is structural rather than neglectful: polish is mostly view code, and the pure halves this phase extracted _are_ well covered (`renderer/app` 83.29% → 85.12%, `renderer/render` 21.05% → 25.77%) while the Pixi and device wrappers they were extracted from cannot honestly be unit-tested — `TESTING.md` §4.1 says exactly that. The denominator grew 334 lines and coverage grew 152. This is the same mismatch flagged at the 07e close, now measurably worse: §4 sets per-area thresholds and never assigns one to devtools, preload, or bootstrap, yet the config counts them all toward a single global 80%. Reconciling that is the work, and it is an owner decision.
- Ground decoration (phase-07.5e — **the world outside the farm is a place now**): trees, rocks, bushes, and flowers scatter the unowned land, from art that already shipped — no new assets. Three rules keep a cosmetic system from becoming a gameplay one, each of them a test: it **touches nothing** (not a building, not an entity, not in the save; a worker walks straight through a bush because the bush does not exist to the simulation); it is **derived, never rolled** — placement is a pure hash of seed and tile, deliberately not `world.rng`, since drawing from the simulation's generator would advance the stream a saved game resumes from and desynchronise every future tick, with a test asserting the generator is byte-identical across a full plan; and it **stays off the farm**, with a tile that becomes the player's losing its tree on the next plan, which is how land expansion reclaims scenery. Props are static and re-planned only on expansion, so render-on-demand is untouched, and they share the y-sorted `objects` layer with buildings so workers, buildings, and scenery interleave by depth correctly.
- UI accessibility (phase-07.5d — **contrast is now measured, and keyboard focus is visible**): WCAG 2.2 contrast maths implemented directly and asserted over every colour pair the HUD uses, measured against a **white backdrop** because a translucent overlay sits on whatever wallpaper the player has — passing there means passing anywhere. Every pair already met AA; the value is that it is pinned, and the helper's own arithmetic is checked against WCAG's stated values so it cannot pass vacuously. It caught a real bug in itself on the first run: `Number('88%')` is `NaN`, so the status bar's `rgb(18 20 26 / 88%)` yielded an `NaN` ratio and three assertions that passed against nothing — the parser now refuses notations it does not understand rather than guessing. **Keyboard focus was almost entirely missing** — exactly one control in the HUD had a focus style, so tabbing through Settings, Shop, Inventory, Hire, Save, mute, or Dismiss showed nothing; one global `:focus-visible` rule now covers every control and every control added later. Minimum target size (24×24, WCAG 2.2 §2.5.8) applied to buttons, a real constraint on a 220 px overlay where several controls were 15–18 px tall.
- Camera focus (phase-07.5c — **the camera helps, and never fights**): an eased glide brings a selected worker or a newly placed building into view, and **declines to move at all when the target is already comfortably on screen** — moving to show something the player is already looking at is disruption, not help. Any pan or zoom abandons a glide instantly, mid-flight, with no easing out and no resumption. The glide lands exactly on its target and holds an animation lease only while running, so render-on-demand is untouched. Two of the directive's four focus triggers were declined on purpose: loading a save already frames the owned plot geometrically at construction, and focusing on every completed harvest would make a companion unusable — harvests fire several times a minute on a mature farm, and the burst already marks the spot. Zoom limits and edge clamping were examined and left alone: clamping already pins correctly when the world is narrower than the viewport, and zoom is already integer-only with the viewport centre preserved, because non-integer zoom resamples pixel art.
- Feedback effects (phase-07.5b — **the world acknowledges you**): a harvest burst on the tile the event names, a confirmation ring on a placed building and a selected worker, a coin popup when a sale lands, an inventory flash when goods arrive. All event-driven and short — **render-on-demand is intact, and the E2E gate still shows a static world drawing no frames**. The timing lives in a pure, unit-tested queue separate from the Pixi drawing, because the property that matters is not that effects appear but that they reliably STOP: an effect that never expires holds the dirty gate's animation lease forever, costing a frame every frame while looking exactly like normal operation. Capped at 12 concurrent with the oldest dropped, so an offline catch-up crediting hundreds of harvests does not make the farm flash like an alarm. Layer 4 (`effects`) was claimed exactly as `layers.ts` reserved it — no re-layering migration, which is what reserving it bought. The two HUD surfaces share one `useGain` primitive; decreases are silent, because spending was deliberate and this feedback is for value arriving while the player looked elsewhere. Both HUD animations are one-shot and disabled under `prefers-reduced-motion`. E2E caught two real regressions on the way: the coin popup, first nested inside the coin readout with `role="status"`, both polluted the balance's text (`1,240+12`) and collided with the companion toast's role — it is now a sibling and `aria-hidden`, which is also the correct call for a visual echo of a number already on screen.
- Audio (phase-07.5a, ADR-016 — **the loop now answers you**): eight placeholder sounds, scripted and deterministic, wired to things that already happened rather than to intents — harvest and sale ride published events; deposit and placement ride settled snapshots; a rejected purchase and an illegal placement stay silent. Three layers with one job each: the catalogue knows what exists, the bus knows what is audible, the device knows a sound is a file — so the bus is unit-tested in Node with no browser, and swapping the placeholder set is a pipeline change with no code in it (drop a real `assets/src/audio/<name>.wav` and the generator copies it through). **Sound ships muted, and work mode silences it unconditionally**: an overlay that makes noise unasked is the worst thing this product could do (`VISION.md` §5.1), so volume joins the companion's presence dials — opacity governs intrusion on the eye, volume on the ear — inheriting main-side sanitization and `settings.json` persistence, never touching the save. Bursts coalesce at 250 ms, because three workers finishing on one tick is ordinary and three overlapping samples are not. The **ambient beds the directive lists were declined**: continuous audio is the audible form of the idle cost ADR-001 exists to avoid, and a sound with no trigger is unreachable code. `ASSETS.md` §3 amended — audio moves from "v0.2+" to shipped. One flake earned its keep: building the eight `Audio` elements at boot turned two E2E specs intermittently slow to reach interactive, so elements are now built on first play and a muted session builds none.
- Save-compatibility gate for v0.1 (`fix/0.1/7.2.md` — verification only, no gameplay): `docs/save-compatibility-report.md` states what the format promises every save file a player will own, and `tests/save-compatibility.test.ts` (45 tests) is the evidence for each claim — exercising the **whole** pipeline (serialize → bytes → parse → migrate → validate → repair → hydrate) rather than any one stage. **`save → load → save` is byte-identical**, not merely equivalent, across seven scenarios (empty, minimum, 1,600-tile large world, 30 workers, full inventory, full storage with a 2-billion-coin wallet, 20,000 simulated ticks) and over **100 consecutive cycles**. Determinism is asserted subsystem by subsystem, and the RNG is proven to resume mid-stream on its next sixteen _draws_. The compatibility rules are now stated and pinned: unknown and additional fields are accepted on read and **dropped by the next save** — the deliberate price of hand-written serialization, recorded in `SAVE_FORMAT.md` §4.5 so no v0.2 author discovers it the hard way. Migration idempotency, ordering, registration, and unknown-version rejection are covered; corruption of every enumerated shape is a typed error rather than a throw. Worst-case budgets measured: an 88,575-byte large world saving in 0.33 ms and loading in 1.03 ms, with repeated saves flat (0.262 → 0.265 ms). **Three mutation controls verified the suite has teeth, and one found a real hole** — deleting RNG restoration passed the first version of the suite because no scenario had advanced the generator; the scenarios now stir it, and that deletion fails five tests.
- Test infrastructure (phase-07e): every Playwright spec now launches on a throwaway userData profile (`tests/e2e/isolated-profile.ts`) — isolation was optional while nothing wrote saves, but an app that saves itself would otherwise write its test farm into the developer's real save and load it back on the next run. `npm run test:coverage` had **never completed**: V8 instrumentation costs roughly 3.5×, which blew the 8-hour behavioural long-run's 240 s timeout and 07d's n = 50,000 property budget, killing the run before the reporter printed — so the thresholds had never actually been evaluated. Timeouts raised, the memory gate now runs uninstrumented (a heap measurement taken under a heap profiler is not a measurement), and the gate reports for the first time: **67.36% lines / 64.30% branches against the required 80% / 75%**. The shortfall is entirely in never-unit-tested code — `main/index.ts`, `preload/index.ts`, `bootstrap/start.tsx`, the PixiJS view layer, devtools — and blocks the v0.1 boundary rather than any milestone. See `docs/phases/phase-07-save-load.md` for the per-area breakdown.
- Offline progress (phase-07d — being away earns): `src/persistence/catch-up.ts` converts a closed app's wall time into closed-form progress — capped at 8 hours, negative time clamped, applied at the load boundary before the loop's first tick, wall clock entering exactly once. Growth is _free_ (advancing the tick is the catch-up — exact by ADR-009's derivation); economy recovery is _exact_ (the batch multiplier form over the period **crossings** the real scheduler would have fired — `floor(elapsed/period)` drifts by one at unaligned starts); worker production is _statistical and provably conservative_: the per-cycle handling constant sits above the real simulation's cost, untilled ground is never newly planted, overflow fills worker carry-holds before anything sells (selling what real workers would still be carrying over-credits coins), and sold units are priced at the worst multiplier the real path could have reached. **The never-over property drew blood before passing**: fast-check compared catch-up against the real simulation on byte-identical clones at n ∈ {100, 1,000, 50,000} across arbitrary farms and shrank the first model's over-credit to its minimal case — one worker, one wheat crop, one wheat seed, no bin — exposing that real workers replant only through the seed bin's per-tile memory (falling back to the _default_ crop without one). The delivered rule mirrors reality: replanting is credited only via the bin + memory; the bin is what makes unattended replanting reliable, and now the catch-up model says so too. Accuracy on the representative mature farm lands within the documented ±10% band, under; blockers report `{reason, atTick}` mid-stream for 07e's return summary; < 50 ms at the 576,000-tick cap, measured. E2E: an app closed for 4 seconds relaunches with at least that time credited as ticks. `GAME_DESIGN.md` §9.2 reconciled to ADR-009 (the moisture-era rows were pre-ADR-009 drift). 811 unit/integration tests, 27 E2E

## Versioning Rules

### Two version numbers

This project tracks **two independent versions**. Confusing them causes save-compatibility bugs.

| Version                 | Format                  | Meaning                     | Where                                   |
| ----------------------- | ----------------------- | --------------------------- | --------------------------------------- |
| **App version**         | Semantic (`0.1.0`)      | The release the player sees | `package.json`, `meta.gameVersion`      |
| **Save schema version** | Integer (`1`, `2`, `3`) | The persisted data format   | `schemaVersion` (`SAVE_FORMAT.md` §4.1) |

They move independently. A patch release may bump the schema; a minor release may not. **Only `schemaVersion` controls migration** — `meta.gameVersion` is informational and must never drive logic (`SAVE_FORMAT.md` §2.1).

### Semantic versioning, as applied here

Pre-1.0, the conventional rules are adapted to the roadmap in `PLAN.md`:

| Bump                | Means                                               | Example         |
| ------------------- | --------------------------------------------------- | --------------- |
| **MAJOR** (`1.0.0`) | v1.0 — the feature-complete life simulator          | Reserved        |
| **MINOR** (`0.2.0`) | A roadmap tier: new systems, possibly a schema bump | v0.1 → v0.2     |
| **PATCH** (`0.1.1`) | Fixes, balance, performance; no new systems         | Bug fix release |

**Backward compatibility is never broken**, at any bump (`AI_RULES.md` §1.4). A v0.1 save must load in v1.0. There is no version increment that licenses breaking a save.

## Entry Format

### Categories

Use these six, in this order. Omit empty ones.

| Category     | For                          |
| ------------ | ---------------------------- |
| `Added`      | New features                 |
| `Changed`    | Changes to existing behavior |
| `Deprecated` | Features to be removed later |
| `Removed`    | Features removed now         |
| `Fixed`      | Bug fixes                    |
| `Security`   | Vulnerability fixes          |

### Writing entries

Entries are for **players**, not developers. The reader wants to know what changed about the game, not which module was refactored.

```markdown
## [0.2.0] - 2026-XX-XX

### Added

- Weather system: rain automatically waters crops
- Plugin loader — mods can now add crops, items, and buildings
- Day/night cycle affecting worker schedules

### Changed

- Wheat growth time reduced from 120s to 100s
- Market Stall now sells at 92% (was 90%)

### Fixed

- Workers no longer stall when storage fills while carrying items
- Overlay re-docks correctly after a DPI change

### Save Compatibility

- Schema version 1 → 2 (adds weather state)
- v0.1 saves load automatically; no player action needed
```

### The Save Compatibility section

**Required on any release that bumps `schemaVersion`.** It must state the version transition and, in plain language, what the player needs to do — normally "nothing."

This section exists because save compatibility is the promise this project makes most seriously, and a release that changes the format without saying so undermines it even when the migration works.

### Rules

- **Player-facing language.** "Workers no longer stall when storage fills," not "fixed null deref in `deposit-task.ts`."
- **No internal refactors.** If it does not change what the player experiences, it does not belong here (that is what git history is for).
- **One line per change.** Link to an issue if there is detail worth having.
- **Add to `[Unreleased]` in the same commit as the change** (`AI_RULES.md` §5.4).
- **Balance changes are always listed.** A player who notices wheat is faster deserves to find it here.
- **Performance improvements are listed when measurable**, with the measurement: "Idle CPU reduced from 1.4% to 0.6%."

## Release Process

1. Verify every gate in `PLAN.md` §8 — **including zero known data-loss defects**
2. Move `[Unreleased]` entries under a new version heading with the release date
3. Add the Save Compatibility section if `schemaVersion` changed
4. Bump `version` in `package.json`
5. Confirm every golden fixture still loads (`SAVE_FORMAT.md` §4.4)
6. Tag the release `v<version>`
7. Create a fresh empty `[Unreleased]` section

Step 5 is not optional and not covered by step 1's general test run. It is the specific check that a released build can still load saves from every prior version.
